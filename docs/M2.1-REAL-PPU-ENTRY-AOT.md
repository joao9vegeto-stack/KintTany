# AscensionRecomp M2.1 — real PPU entry probe + reproducible ARM64 codegen

Scope: God of War Ascension PS3 NPUA80918 -> iPhone 17 Pro ARM64; other branches are untouched.

## Private proof completed (nothing copyrighted or confidential pushed)
- Parsed the actual private GOWA.ELF, verified PowerPC64/Cell LV2 and executable segments.
- LLVM `llvm-objdump -d` disassembled 1,633,592 4-byte instructions in non-zero regions, 263 distinct instruction mnemonics. This is an ISA census, **not** claimed recompilation/coverage of the full game.
- Implemented generic, strict subset AOT translation: PowerPC64 -> freestanding C. Unknown opcode raises instead of issuing NOP or silent success.
- Real entry function from 0x10410: translated 13 PPU instructions into a 1,160-byte C source (li, oris, ori, lwz, stdu, std, bl, nop, extsw, blr), and compiled with Clang `-target arm64-apple-ios17.0 -ffreestanding -c` into 688-byte **Mach-O arm64 object**.
- SHA256 of private arm64 object: 285cc906298e30c24adb57974572d774f0ed0a819ef45f2ec84ee7fa5f25ca75.
- A host-only harness with mock guest-memory callbacks checked computed values for r2, r3, r1 stack update, linked branch destination 0x10534 and return LR. Harness passed.
- **Neither object nor commercial-game-derived C, ELF, RAP or PRIVATE data is committed to the repo.**

## Public CI proof
- Existing pinned PS3Recomp lib macOS/arm64 plus original synthetic full-loader/lifter check.
- New `tools/ppu_lift_probe.py` implements a portable, strict subset translation and read-only ELF PT_LOAD extraction.
- New synthetic tests reject unsupported instructions (no invisible fallback), require a proved `blr` and cover the minimal opcodes.
- Cross-compile generated **synthetic** C to **arm64-apple-ios17.0 Mach-O** with Clang. If unsupported by runner, CI must fail visibly.
- No commercial executable or license on GitHub runners.
- One commit; only the `AscensionRecomp` workflow executes.

## Open limitations (real)
- This is ONE real function, not 7643 functions. The iOS .o is not an IPA and does not yet link to a real PS3 runtime.
- The host harness uses mocked memory; correct full-game execution and actual device stability remain unproven.
- The generic micro-lifter supports a small instruction subset. Use upstream PS3Recomp for full lift and coverage metrics; do not mistake the private ISA census as upstream lift performance.
- CPU host-call ABI, PPU Thread, SPU/SPURS, DMA, PSARC resources, RSX and HLE still require implementation.
- Next: map other function ranges, quantify unsupported instructions vs upstream, link with runtime and assemble first minimal boot trace.
