# AscensionRecomp M2.9 — First PS3 CRT HLE crossed, privately

The first boot import identified in Ascension NPUA80918 is:
- Guest trampoline 0x669C0C
- NID 0x744680A2 (sysPrxForUser / sys_initialize_tls)
- The PS3Recomp pinned upstream already has context-aware implementation of
  this CRT service in runtime/ppu/ppu_sysprx.cpp.

M2.9 implements a small, **bounded and single-thread only** TLS handler in
the test bridge. It copies initialized PT_TLS template bytes, zeroes BSS,
sets guest r13 = guest-block + 0x7000, and returns CELL_OK only when this
real initialization operation completes with validation. It rejects invalid
lengths and exhausted guest TLS space. No scene-specific fixes or masked
unimplemented calls.

**PRIVATE real-ELF trace:** GOWA ELF PT_TLS at 0x839B28, file data 12 bytes,
memory size 0x180; a bounded guest TLS region was configured at 0xC00000.
With actual translated private PPU functions 0x10410 and 0x10534 loaded,
the first sys_initialize_tls call completed and set r13 to 0xC07000.
The next missing PPU call is now 0x531CAC, LR 0x10604. This is a
deterministic **partial startup trace**, not game boot or functional assets.

The GitHub branch contains only generic implementation and **synthetic**
memory/native tests and compiles the code for iOS ARM64. No GOWA executable,
licenses or game-generated C are committed or sent through CI.
