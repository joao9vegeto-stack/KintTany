# M2.2 — Bounded PPU batch probe, 2026-10-14

**Scope:** AscensionRecomp only, iPhone ARM64 target. This repository contains
no game binary, decrypted ELF, RAP, PKG, or lifted commercial executable.

## Locally validated on user's private Ascension executable
A separate extended strict AOT prototype (delivered to the user as a private
conversation archive, *not committed*) reported **1,744** of 7,643 OPD entries
as straight-line candidates. All 1,744 generated C functions compiled together
with Clang for target arm64-apple-ios17.0 into a 396,464-byte Mach-O object.
Four additional synthetic host semantic checks passed, including CR0 compare,
rlwinm rotate, addic carry in XER, and stdu stack update with RA=RS.

**These are candidate translations, not proof of behavior, coverage, or gameplay.**
No linked runtime, iOS IPA, GPU, SPU program or game boot exists yet. The
strict local prototype refuses unsupported branches/instructions and rejects
functions whose declared range does not terminate at a final BLR.

The public repo now contains the generic smaller batch checker
tools/ppu_m22_bounded_batch.py. It tests strict declared-range handling and
generates a synthetic 2-function ARM64 Mach-O compilation in GitHub Actions.
The repository-side subset is narrower than the separate private experiment;
do not conflate synthetic CI results with the real 1,744-function measurement.

## Next gate
Use upstream full PS3Recomp PPU lifter on the **private** GOWA.ELF, with
bounded work partitions; measure branch CFG correctness, indirect calls,
unimplemented opcodes and C++ compiler failures. The largest blocked opcode
in the private small lifter is conditional branch primary 16; production
implementation requires full branch semantics, CR/CTR consistency and
differential testing rather than silently mapping branch to NOP.
