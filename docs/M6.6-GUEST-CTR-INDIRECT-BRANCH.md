# AscensionRecomp M6.6 — PowerPC CTR, mtctr and bounded indirect guest branch

Physical screenshot after M6.5.3 (real GOWA.ELF NPUA80918):
M6.3 real PPU 24/24 OK; M6.4 LEGADA -995 at 28/32
correctly transferred into the M6.5 guest writable PT_LOAD;
M6.5 PARADA SEGURA -990 at 38/40, PC=0x669C2C,
raw instruction 0x7C0903A6 = mtctr r0 (mtspr SPR=9, RS=0).

M6.6 adds a new bounded 48-step CPU interpreter, strictly replaying
the private ELF from OPD with 4KiB guest stack and the known safe
writable PT_LOAD overlay, WITHOUT modifying old M6.0..M6.5 probes.
New mtctr decodes the swapped 5-bit SPR number; only SPR=9 and Rc=0
are accepted. Supports mfctr and previous mflr, unconditional bctr
and bctrl only; validates 32-bit executable guest address and
alignment via PT_LOAD before any jump. Conditional bcctr variants
requiring CR model reject closed. No title bytes, RAP or proprietary
code are included in GitHub or IPA.

UIKit allows a retry into M6.6 only if the old M6.5 stops with -990
on exact valid mtctr after >=32 steps, after M6.3 and safe M6.4
legacy gates. Other errors still return immediately. The UI never
mislabels legacy M6.5 as 40/40 when it stopped at 38/40.
Per step, the new interpreter clears previously saved guest EA/base/
store value so a new unsupported opcode cannot be falsely
attributed to an old memory operation. Guest CTR and indirect count
are reported for instruction failures, and effective address only
when current instruction fault was memory-related.

Host CI fixture: synthetic ELF traverses 48 instructions, mtctr
r0, bctr to mapped guest code, bctrl return LR, invalid unmapped
CTR rejected, CR-dependent branch rejected, non-CTR SPR and Rc
rejected, stale EA cleared. This is NOT a full PS3 native game boot.
