# AscensionRecomp M5.0 — native iPhoneOS VP/FP shader compiler (experimental)

Baseline (preserved): M4.10 HEAD 697d279b6bd0bf5b791385c0f363c77e9da7099e,
device-proven LINEAR and SWIZZLED mutable cache and older NV4097 probes.

## Real implementation

Pinned ps3recomp code already contains NV40 VP/FP decompilers to HLSL,
glslang HLSL -> SPIR-V and SPIRV-Cross SPIR-V -> Metal. Until M4.10,
the iOS runtime compiled the *stub* implementation and kept s_guest_shaders=0.
M5.0 cross-compiles Khronos libraries for iphoneos/arm64 from pinned sources,
sets PS3RECOMP_HAVE_MSL_TRANSLATION=1, emits MSL in iOS mode, links all
native static archives into the diagnostic IPA, and retains the M4.5
fixed-shader pair for legacy tests.

Sources pinned by SHA in CI, fetched only into the disposable runner:
- glslang 8a85691a0740d390761a1008b4696f57facd02c4 (15.4.0)
- SPIRV-Cross 300681bbcb8365a8d1eacdacdbdd0249bbf1d6b1
No games/assets/keys are ever uploaded.

The **M5.0 · Shaders RSX VP/FP** button runs a bounded real NV40
microcode test on the physical device:
1. 2-instruction VP MOV -> HLSL -> SPIR-V -> MSL -> Metal vertex main0
2. 1-instruction FP MOV -> same -> Metal fragment main0
3. 1-instruction FP TEX0 -> same -> Metal fragment main0, require
   [[texture(0)]] + [[sampler(0)]]. Any failed stage returns a code.

Host CI runs ps3recomp's test_shader_msl synthetic microcode cases and
its PPU/LV2 boot-smoke binary. These are not GOWA boot tests.

## Acceptance and next gate

CI success is *not* a hardware success. Require a new physical iPhone capture
that reports 3 compiled guest stages before marking M5.0 hardware OK.
Even that result only proves shader compilation, not final RSX draw
or texture sampling by a real guest fragment pipeline. Next M5.1 gate is
TEX0 flowing through a draw that executes this compiled FP, pixel by pixel,
without compute diagnostic; then private GOWA PPU/SPU/LV2 startup trace.
Do not claim game functionality or 30/60 FPS without actual gameplay.

Regression checklist: long press triangle; 1/2/3/4/5 taps; M4.10
three mutations in both layouts. Real translator must not substitute
unknown shaders with a stale pipeline. Re-check framebuffer on hardware.

No GOWA.ELF/RAP/PSARC in repository, CI or its artifacts.

## M5.0.1 — failure evidence and targeted fix

The M5.0 Actions run 38788775605 passed the macOS guest-shader translation
suite, but the first integrated boot smoke failed on a **headless Mac runner**:
11 ordered PPU markers, 3 guest flip requests, and sys_process_exit(39) were
observed, while 0 backend frames presented and 0 vblank calls were observed.
The existing upstream boot scaffold selects Metal on Apple even without an
onscreen drawable, so its graphics-presentation assertion is not a valid
CPU/LV2 regression on this runner. M5.0.1 enables the upstream headless
software RSX backend **only for ps3recomp_boot_smoke**, with an isolated
compile definition. The real app remains Metal. The smoke still asserts
3 FIFO flips, 3 presentations, vblank, PPU thread, HLE and exit; no bypasses
or fabricated CELL_OK values. A failure is a real gate failure.

## M5.0.2 — iPhoneOS cross-compiler include path

M5.0.1 Actions run 38789295200 passed synthetic PPU/LV2 boot and all
upstream synthetic CPU regressions. The iPhoneOS RSX shader translator
compilation then failed at `glslang/SPIRV/GlslangToSpv.h` because the
cross-compile includes glslang/ but not the parent folder that contains
it. The disposable upstream overlay now includes `${AR_SHADER_DEPS}`
alongside the SPIRV-Cross headers. No GPU/UI/CPU behavior changed.
