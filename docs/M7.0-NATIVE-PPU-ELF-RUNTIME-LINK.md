# AscensionRecomp M7.0 — native iPhoneOS PPU runtime staging (2026-10-16)

## Proven physical-device evidence
NPUA80918 private GOWA.ELF on M6.7.6:
- 48/48 bootstrap steps, return code 0;
- sys_initialize_tls executed with thread=1, template guest VA
  0x00839B28, file=12 bytes, memory=384 bytes, r13=0x0E007000;
- guest returned through mtlr/blr and latest reported PC=0x1059C.
This is the bounded interpreter's success, not game boot.

## Prior architecture gap (verified in repository)
tools/build_ios_ppu_core.sh produced libAscensionPPUCore-ios-arm64.a
from runtime/ppu_bridge.c, runtime/elf_image.c, runtime/ppu_tls.c,
LV2 and thread services. tools/build_ios_probe_ipa.sh, however,
only linked the RSX/Metal archive and ARPrivateELFProbe.c.
The existing runtime was NOT part of the app executable.

## M7.0 actual implementation
The IPA now compiles ios/ARLivePPUBridge.c for iPhoneOS arm64 and
links ios-ppu-core/libAscensionPPUCore-ios-arm64.a (plus RSX Metal).
The iOS app passes the same private in-memory ELF bytes, observed
guest PRX stub and copied diagnosis to ar_m70_native_runtime_probe.
The new C adapter:
- validates ELF64 big-endian PowerPC, bound-safe PT_LOAD sizes and
  PT_TLS metadata, rejecting >128 MiB guest allocations;
- allocates one isolated guest VM just large enough for loaded
  segments + 64KiB TLS and 64KiB guest stack;
- calls the real ar_load_elf_image and reports entry PC, TOC,
  segment count, bytes loaded and guest first opcode;
- checks the exact actual PRX import via the existing NID parser,
  registers its real sys_initialize_tls handler in the NATIVE
  dispatcher, and independently invokes that handler on the staged
  guest template (smoke diagnostic, not claiming guest CRT execution);
- calls the actual ar_run() AOT dispatcher at the original ELF entry.
  With zero game-specific ARM64 functions linked, this MUST return
  AR_UNRESOLVED (-3) and the exact missing entry PC. No fabricated
  return, no executing PS3 bytes as iOS code, no JIT entitlement.
- discards the native guest VM before returning to UIKit.

Both diagnostic streams are copied by one button. A failed staging,
  rejected import, successful native HLE, or unresolved AOT entry are
  reported separately to avoid treating compilation of native library
  as actual native game recompilation.

Host CI uses only a synthetic ET_EXEC+PT_TLS+PRX ELF:
positive loader+HLE+missing AOT, repeat-isolation, unmatched import,
wrong NID, invalid ELF header, and guest address beyond 128 MiB.
CI inspects the final IPA's native symbols ar_run, ar_load_elf_image,
ar_sys_initialize_tls and ar_m70_native_runtime_probe. Legacy PPU48
and M4/M5 GPU tests remain active. The user's ELF is never uploaded.

## Actual next gate: native recompilation
M7.0 is necessary infrastructure but NOT the complete Ascension port.
The game executable cannot be linked from an on-device GOWA.ELF
into a signed ARM64 app without an AOT compilation/signing workflow.
The existing general-purpose tiny lifter is insufficient for all
Ascension PPC opcodes and functions. The next step requires
a private lift+compile pass using the user's authorized decrypted
ELF (not in a public CI, commit or IPA), with coverage, relocation
and ABI validation. Until then native ar_run correctly reports
AR_UNRESOLVED at the original game entry.
