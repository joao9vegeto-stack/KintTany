# AscensionRecomp M4.2 — iPhone Metal visible GPU presentation probe

## User-observed baseline

On iPhone 17 Pro, M4.1.1 app shows a black background plus
'Metal inicializado pelo backend RSX'. Thus UIKit launch, CAMetalLayer
binding, and backend initialization returned success on actual hardware.
Black screen proves NOTHING about submitted or displayed GPU frames,
because no real render commands from Ascension were supplied.

## M4.2

Retains the pinned CPU/SPU/LV2 + RSX→Metal backend, and after successful
backend init, uses the SAME CAMetalLayer/MTLDevice to issue a real
Metal render pass with loadAction=Clear, storeAction=Store; submits
a command buffer, calls presentDrawable, waits for GPU completion, and
checks its completion status. Background becomes BLUE, GREEN, PURPLE
on successive taps; a status label reports successful completed
submissions or displays actionable error details. This shows that the
native iPhone layer/device/presentation route works, not that guest
RSX commands from God of War can render textured scenes.

## GitHub validation

One branch-filtered Actions compiles the iOS executable, creates unsigned
AscensionRecompProbe-0.4.2-unsigned.ipa, checks its Info.plist version and
ZIP integrity. CI cannot prove on-device display output; the user supplies
a new screenshot following sideload.

## Limits

No Ascension game executable/asset/license is distributed, no SPURS game
boot or correct RSX texture pipeline has yet been tested. No game frame-rate
measurement or claim of 30/60 FPS. Any game media remains private, not
committed or uploaded to public Actions. No other branch touched.
