# AscensionRecomp M5.8.1 — correct alpha-zero GPU oracle

**Physical iPhone evidence 2026-10-15:** Both LINEAR and SWIZZLED
reported `M5.8 ALPHA: FALHA -828 · fase 3`, DRAW 3/3/2, four
ordered GPU pixels `000000FF FF0000FF 00FF0000 FFFF0000`.
Every other test M5.1–M5.7 reportedly remains functioning.

**Verified cause:** The previously implemented expected-pixel table
incorrectly assumed a fragment passing LESS 128 but containing alpha=0
would write opaque alpha=255. RSX/Metal actually **writes alpha zero**,
which is correct. The pixel mismatch is at phase index 2, quadrant 0:
`-820 - (2*4+0) = -828`. q2 also changes alpha to zero.

**Fix:** ONLY the expected GPU readback oracle is corrected; guest
state, shaders, alpha compare functions, GPU frame sequence, source
texture alpha values, depth/stencil and blending remain untouched.
Pass3 expected `000000FF FF0000FF 00FF0000 FFFF0000`.
Pass4 rejects all (GREATER 255) and must preserve pass3 including alpha.
Pass5 (GREATER 0) updates only opaque right half, preserving zero alpha
on left: `000000FF FFFF0000 00FF0000 FF0000FF`.

CI adds an independent Python oracle simulating the fixture only.
It **does not** claim to verify live Metal GPU; physical iPhone test
LINEAR/SWIZZLED must pass all FIVE GPU draws and 5/5/4 counters.
Regression tests from M5.1-M5.7 remain active, no other branch touched.
No game executable/assets in this probe. No full Ascension gameplay or
30/60 FPS claims.
