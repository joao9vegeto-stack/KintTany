# M8.06 — native lift for the captured WWS branch

The M8.05 device export contained 18 rows but only three distinct 64-byte fragments.

| Local-store PC | Overlay | ELF match | Finding |
|---|---:|---|---|
| `0x04038` | 201 | Unique match at file offset `0x6E7238` | ELF-backed branch; lifted to native PIC |
| `0x3FEC0` | 0, 200–229 | No match, even on the first four bytes | Runtime-generated save/restore stub; not liftable from the ELF |

The `0x04038` sequence belongs to the WWS module beginning at ELF EA
`0x006F7200`. The PIC lifter emitted two native functions from a 112-byte
region: the captured `0x04038` entry and the module's `0x04030` return
target. There were no unsupported SPU instructions in this lift. The build
registers this PIC region before starting SPU workers and checks that the
captured entry is present in the final Mach-O.

The 16-word sequences at `0x3FEC0` decode as sixteen `stqa` or `lqa`
operations over registers r0–r15. The PC port's
[`map_spu_fragments.py`](https://github.com/RichardFontoura/gowa-pc/blob/main/scripts/map_spu_fragments.py)
classifies this address as generated runtime code. The PC port's
[`lift_spu_fragments.py`](https://github.com/RichardFontoura/gowa-pc/blob/main/scripts/lift_spu_fragments.py)
also searches ELF-backed bytes, while the Ascension PC
[patch 0031](https://github.com/arnaldolima1/gow-ascension-pc/blob/main/patches/ps3recomp-0031-spu-fragments-by-content.patch)
adds content-based discovery for registered PIC fragments loaded inside larger
GETs. Neither can map the `0x3FEC0` stub to a static ELF origin. That dynamic
stub remains a separate runtime path; this build does not claim it has been
statically lifted.

The prior generator required eight unique ELF-backed entries and rejected this
capture. Its default now accepts one entry, which matches the evidence in this
export.

## Validation

- Reproduced against the supplied NPUA80918 ELF and PIC export with
  `--min-entries 1 --margin 0x10`: one ELF offset found; two native functions
  emitted; no unsupported instructions.
- The M8.06 workflow compiles and links the PIC source and verifies the exact
  native entry symbol in the ARM64 Mach-O and IPA.
- An on-device render still requires an iPhone run showing guest draws, guest
  flips, and the game image. A successful IPA build alone does not prove that
  this new entry clears the black screen.
