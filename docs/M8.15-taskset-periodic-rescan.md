# M8.15 — periodic native WWS taskset rescan

## Evidence

The M8.14 device report still has four tracked tasksets, zero candidates/valid tasks, six active runners with no returns, and 79,642 SPU PUTLLC line commits. The existing M8.08 callback only calls the ready-task scanner when the committed reservation line exactly matches a tracked taskset's first 128-byte line.

The report does not expose the ready/pending/enabled bitsets at the instant of each commit, so the line-match hypothesis is not proven. This change adds a bounded recovery scan rather than claiming a root cause that telemetry cannot establish.

## Change

- Keep the immediate scan when a PUTLLC/PUTLLUC commit matches a tracked taskset base line.
- Every 64th aligned atomic-line commit, scan all tracked tasksets as a fallback for missed or aliased notification paths.
- Reuse the existing production scanner unchanged: it still requires real ready/pending bits, enabled state, valid guest ELF, and the running-bit guard. No task is synthesized and no completion/draw/flip is fabricated.
- Extend the host regression to put a valid ready task in guest memory, deliver 64 commits for unrelated lines, and prove the real scanner dispatches it once; subsequent matching commits must not duplicate it.

## Verification boundary

CI can prove the scanner's fallback behavior and package the ARM64 IPA. Only a device run showing candidates/valid tasks increasing, task returns or completed work, and real guest frame pixels can prove that this fixes the current Ascension stall. This is a scheduler recovery measure, not a claim that XOWUE's Xenos renderer or game-specific continuation addresses can be copied into the PS3 RSX path.
