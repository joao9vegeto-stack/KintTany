# M8.07 — usable live report, exact PIC filtering, and guest flip fallback

## Evidence from the M8.06 run

The supplied M8.06 screen recording shows a black game surface. Opening the report displayed only “Relatório vazio: nenhuma métrica foi retornada.” The companion PIC capture contains 17 rows at LS PC `0x3FEC0`, across overlays 200, 201, 205, 213, 216, 224, 226, and 229. Those rows are two exact 16-instruction variants of the runtime-generated stack bridge. They are not evidence that the guest ELF supplied a reusable SPU function.

M8.06 also linked the static PIC symbol `pic_006E7220_spu_func_00000018`; symbol presence alone does not establish that a worker looked it up or returned from it.

## Concrete changes

| Area | M8.06 | M8.07 |
|---|---|---|
| Report button | The screen showed the generic empty-report fallback. | The modal formats a bounded live snapshot directly on the main thread, with a non-empty header and explicit partial-snapshot errors. It includes PPU entry state, guest filesystem activity, SPURS/WWS task and stack counts, PIC lookups/hits/misses, GCM events, guest draw/flip counters, and the existing sampled backedge/register snapshot clearly labeled as not being the current instruction PC. |
| SPU PIC capture | Repeated the generated stack bridge as if it were useful captured code. | Filters only the exact 64-byte bridge at `0x3FEC0`, accepts both observed encodings, and rejects mutations or mixed encodings. Filtered stubs, saved rows, PIC table size, and native lookup hits are counted separately. |
| Frame presentation | Presented only when the synchronized pending-flip flag was observed. | Also presents when the guest's monotonic flip-request count advances, matching the fallback used by the PC frame clock. It still drains the real guest FIFO and never fabricates a draw or guest flip. |

## Validation boundary

The host test compiles the actual C predicate extracted from the PIC patch and checks both bridge encodings, the exact PC, a mutated byte, and mixed encodings. Source-contract checks cover report contents and the flip fallback. The iOS workflow must additionally compile and link the app, check the three new symbols in the final arm64 Mach-O, and validate the IPA archive.

These checks do not prove that the game renders on an iPhone. M8.07 is only validated for device rendering if the live report shows positive guest draws and presented guest flips and the recording shows actual game pixels. If those remain zero, the new report will expose the missing stage instead of substituting the old empty fallback.
