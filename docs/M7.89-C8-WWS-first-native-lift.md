# M7.89: exact C8 WWS policy lift

## M7.88 evidence reviewed

`Arquivo.zip` at the root of `AscensionRecomp` contained `788.mov`, `788.txt`
and `spupm_C8D774963A96DCF2_12288.bin`. The binary is 12,288 bytes; its SHA-256
is `2cdc171545c7874a12ec85646fe0456a9cb4f62c7576bcd571a705799be34e99`, and
the runtime's FNV fingerprint is exactly `C8D774963A96DCF2`. The video shows
the live report, with no game image.

The report does not sample the current PPC instruction. `0x00669A14` is the
most recently entered AOT function. It is an HLE import stub for
`sys_lwcond_wait` (`NID 0x2A6D9D51`), called with LR `0x004D653C`; the trace
also repeatedly visits `0x0049CD6C`, `0x0066640C` and `0x004D6504`. This is a
condition-wait/poll path, not evidence that the processor is stuck at the
instruction address `0x00669A14`. The report labels `0x003C4FA4` as a hot-loop
marker and explicitly says it is not the current PC.

The functional stop before rendering is identified by the SPURS counters:
18 workloads all supply the C8 policy module at EA `0x007A7B00`, size 12 KiB,
but M7.88 resolves zero of 18 PMs and admits zero WWS workloads. Title job-chain
requests, guest draws and presented flips are also zero. M7.87's 3.44 million
admissions did not mean jobs had run: that build incorrectly mapped C8 bytes to
the unrelated NPUA lift, whose `0xA00` entry is a `stop 0x94`. M7.88 correctly
removed that alias, exposing the real missing step: the C8 module had no native
lift or registry entry.

## Native patch

- Lift the exact C8 bytes with ps3recomp at local-store base and entry `0xA00`.
- Detect 194 function ranges and split SPURS resume addresses. Four candidates
  at `0x1640`, `0x1650`, `0x1660` and `0x1670` are metadata slots with exact
  words checked by the generator and no branch/call references. Excluding those
  slots leaves 255 native functions and zero unsupported instructions.
- Leave the one external target, `0x3FEC0`, to PS3Recomp's generated SPURS
  kernel stub. The lift fails closed if the input hash, metadata bytes,
  function count, unsupported set or external-target set changes.
- Register fingerprint `C8D774963A96DCF2` separately as SPU image 6. The NPUA
  policy remains image 5 and is never used as a substitute for C8.
- Call the C8 registration during PS3Recomp runtime initialization and verify
  the entry and registry symbols in the archive and final iOS Mach-O.

The captured `.bin` is not copied into the IPA or committed as a raw file. The
generated C, lift manifest, and a generator that accepts the captured module
are included in this patch.

## What the next device run must establish

This patch addresses the first demonstrated stop, before title job dispatch.
It does not establish that a frame now renders. The next iPhone report must
show the C8 PM resolving to image 6. Then:

1. If the PM resolves but WWS admissions stay at zero, inspect the SPURS PM
   dispatch boundary.
2. If WWS admissions rise while job-chain requests stay zero, inspect the
   game's PPU-to-job-chain path; do not count scheduler admissions as jobs.
3. If title jobs run but guest draws/flips stay zero, inspect the RSX GCM/FIFO
   submission path reached by those jobs.
4. Only guest draw > 0, presented flip > 0 and a device video of the game's
   image count as a first frame.

PoPTST is a useful native-launcher and direct-render reference, but it is an
Xbox recompiler with a different ISA and runtime. It cannot supply Ascension's
PS3 SPURS/WWS policy or RSX implementation. GoW2/Ascension PS3 references remain
the relevant comparison for those services.

The M7.89 source and lift are ready for the Apple CI build. iPhone execution,
WWS dispatch, game jobs, guest draws and guest flips remain `NOT_MEASURED` until
the device installs and runs the resulting IPA.
