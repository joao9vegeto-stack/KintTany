# AscensionRecomp M3.0 — LV2 syscall opcode lowering, no silent fake

The generic PPC64 lifter now recognizes exactly instruction 0x44000002
(PS3 `sc`), lowering it to ar_guest_syscall(ppu_context*) while preserving
guest registers. Unsupported encodings or absent syscall numbers FAIL,
with the missing LV2 number recorded. Dispatcher reads r11, the PS3 syscall
number. Only explicitly registered callbacks are invoked.

One genuine LV2 API semantics module is implemented for smoke validation:
sys_memory_get_user_memory_size syscall 352 writes the PS3 memory-info
structure (256MiB total, 192MiB free at boot) as two big-endian words into
guest memory and returns CELL_OK only after the write. Bounds violations fail.

CI creates its own synthetic PPU guest instruction sequence calling syscall
352; it must fail when missing, pass with registered handler, and generate
iOS ARM64 object code. No game binaries or license are uploaded.

Private finding from Ascension GOWA.ELF: startup path reached 0x531CAC.
That function calls a routine at 0x531A74 which contains syscall 352 and
403 (TTY output) and a first sys_lwmutex_create import (NID 0x2F85C0EF).
The full 0x531A74 function spans multiple return blocks and still fails our
conservative full-range terminator check; it has **not** been safely lifted,
linked or executed as a whole. This step enables its syscall instruction
semantics without claiming completed boot.

Only the AscensionRecomp branch and its one branch-filtered Actions workflow
are used. No iOS IPA, SPU, RSX or measured FPS yet.
