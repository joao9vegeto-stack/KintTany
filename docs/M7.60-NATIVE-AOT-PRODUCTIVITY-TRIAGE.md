## M7.60 efficiency improvements (runtime only, no new guest code)
1. Preserve the **first 256 unique AOT entry PCs** in exact first-visit order, with `first_total` and an explicit truncation indicator. Nothing is synthesized from a static graph.
2. Preserve the **last 128 AOT runs** as `PC, number of consecutive hits` (run-length encoding), and `run_total` for truncation. A loop of 100 hits becomes one run. All dispatches and executed distinct counts still come from the original native counters.
3. At *actual AR_UNRESOLVED* capture the immediate previous AOT PC (previous dispatch, **not a guaranteed PPC call-site**), plus CR, XER, LR, CTR, GPR1 stack pointer, GPR2 TOC, and GPR3. No contents of memory or game assets are copied into triage.
4. Serialize one-line machine-readable `AOT_TRIAGE_JSON=` with `schema=ascension-aot-triage-1`, arrays `first_aot`, `recent_runs`, `missing_pc`, `previous_aot`, live counters and guest FS counters. Preserve the TXT human-friendly for existing workflows. Legacy raw tail now prints only 16 entries, explicitly labeled.
5. A reproducible **offline next-lot planner** `tools/triage_owner_aot_report.py` ingests `--report device.txt --elf GOWA.ELF [--output candidate.json]`. It verifies actual guest stop vs original executable PT_LOAD (and live guest word when present), builds a conservative sequence of BE PowerPC words up to a control-flow split, and includes runtime first-visit / RLE evidence if available. It marks `candidate_is_function: false`. It **does not** assume direct call targets are compiled, does not invoke sys_fs or alter the iPhone guest.
6. Tests with a 100-hit synthetic AOT hot-loop and an actual missing PC demonstrate recording first visit + compressed runs + registers, with interpreter explicitly disabled via `ASCENSION_NATIVE_ONLY`, and repeated execution reset. Separate offline unit tests check BE ELF and mismatch refusal.
