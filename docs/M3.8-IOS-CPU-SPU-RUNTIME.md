# M3.8: first CPU/SPU/LV2 device-targeted upstream runtime attempt

This stage builds upstream PS3Recomp `ps3recomp_runtime` as a static
iphoneos ARM64 archive. CI checks out the exact MIT source revision
`39a36296511c445707adabcd312f0b740cfbd694`, the same revision used to
generate the M772 game HLE registry. A revision-equality check prevents the
guest registry and host services from silently drifting apart. The overlay
modifies only the disposable checkout inside the CI job.

Known desktop-only dependencies are excluded explicitly:
- `cellPad` uses the app's virtual pad input on iOS; `cellAudio` retains guest
  mixing, ports and event notifications with a silent output adapter.
- The iOS overlay supplies a UIKit `CAMetalLayer`; the desktop
  `NSWindow`/`NSApplication` path is not linked into the app.
- AppKit is not linked against iphoneos. iOS framework links are Foundation,
  UIKit, Metal and QuartzCore. PPU, SPU, LV2 and the pinned HLE service modules
  remain in the runtime archive.

The CI step is intentionally a **real build requirement**: any remaining
cross-compilation error or missing generated HLE service symbol fails the run
before the app link. This produces a native CPU/SPU/LV2/HLE archive and the
Metal presentation path, but does not establish that Ascension reaches its
menu or renders gameplay; those require the user's game data and device report.

All tests use synthetic data; user-supplied PS3 code/assets/license remain
private and do not enter public GitHub artifacts.
