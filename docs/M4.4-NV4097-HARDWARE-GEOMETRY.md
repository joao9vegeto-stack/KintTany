# M4.4 — Hardware geometry test, preserving M4.3 success

USER-SUPPLIED M4.3 VIDEO (2026-10-15, 15.9s):
- RSX NV4097 color clear, GPU flip and center-pixel readback all PASSED.
- Exact observed/expected values: FFFF5828 (orange),
  FFF6BC24 (amber), FF38CAE8 (cyan).
- Video shows repeated successful submissions, NOT FPS.
- FIRST screen was BLACK although it claimed "Referência Metal: AZUL":
  a backend_present() immediately before direct-Metal reference could
  overwrite the first blue frame; and its return was never checked.
  M4.4 removes the first unnecessary backend_present and only says BLUE
  after the actual clear command buffer completed successfully.

NEW: On iPhone, a long press invokes a separate synthetic
NV4097 geometry test, modeled on pinned
libs/video/tests/test_rsx_draw_engine.c:
- Synthetic framebuffer clear to dark blue
- NV4097_SET_VERTEX_DATA_ARRAY_FORMAT ATTR0 = float4
- NV4097 constant COLOR0 (ATTR3) = green RGBA
- NV4097_SET_BEGIN_END(TRIANGLES)
- Twelve 32-bit NV4097_INLINE_ARRAY words, representing 3 vertices
- NV4097_SET_BEGIN_END(0) and guest-driver flip 0xE944
- GPU readback checks that center pixel is green-dominant, and reports
  explicit error codes if the draw, pipeline, or presentation failed

Single taps STILL cycle previously proven M4.3 colored clears.
