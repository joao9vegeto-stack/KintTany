# M7.72 → M7.73: boot ABI and passage criteria

The M7.72 device report showed one host entry call, PC `0x10410`, and no guest
file calls. The call count was misleading because it omitted AOT calls made
inside the guest function. The old bridge also sent a complete PS3Recomp C
function through the legacy PPC fragment runner.

M7.73 changes the entry bridge to invoke `_start` as a complete native function,
matching the pinned upstream `ppu_run()` call-and-trampoline behavior. The
reconstructed lift now inserts a live entry counter into all 29,849 complete
PPU functions. The app can report AOT function calls and the last guest PC
while the background entry is running, alongside real guest filesystem calls.

Build success will prove the ARM64 lift, entry hook, and app link. It will not
prove device execution. The next device gate is rising AOT calls followed by
successful guest file reads. The renderer is still not connected to game RSX;
first frame, menu, gameplay, and measured FPS remain unproven. Full evidence and
the PC/GoW2 comparison are in
[`AUDITORIA-FLUXO-IOS-M7.72.md`](AUDITORIA-FLUXO-IOS-M7.72.md).
