# M7.72 boot ABI and passage criteria

## What the latest device run proved

The video shows that selecting the game folder and importing the ELF work, the
M7.72 static PPU/SPU lift is linked, the runtime binds the selected directory
as its VFS root, and the live report stays responsive. It does not show a game
boot. The report's `Despachos PS3Recomp=1`, last PC `0x00010410`, and zero
guest `cellFsOpen`/`cellFsRead` calls mean the guest CRT entry returned before
title file I/O. The `M7.43` text on the home screen was stale branding; it was
not the version running.

## Integration made in this change

The iOS path uses its own ELF loader and selected-folder VFS, so replacing it
with upstream `ppu_run()` would discard the app's file-provider ownership. The
runtime now reproduces the process-entry contract from the pinned PS3Recomp
`ppu_run()` implementation before entering the ELF OPD:

- register the guest main thread and its reservation context;
- install the initial PT_TLS image and set `r13`;
- pass a big-endian PS3 `argc/argv/envp`, including the disc boot path;
- retain live dispatcher and guest filesystem counters as the evidence of
  whether the CRT progresses into title initialization.

This adapts the relevant entry setup in
`sp00nznet/ps3recomp` (pinned by the workflow), while preserving the iOS
security-scoped folder and native VFS. The GoW2 iOS port's useful pattern is
running guest preparation/execution away from the UI thread and presenting the
game only after the render backend reports a real guest frame. The app already
does its import/probe work in a background queue, but it still has no Ascension
RSX-to-Metal path or first-frame gate. The Ascension PC port's launcher and
staged status/log handling are useful lifecycle references; its experimental
9-fps desktop report is not evidence of iOS compatibility or a portable
renderer.

## Passage criteria against this branch

| Criterion | Current evidence | State |
|---|---|---|
| M0 | CI builds the pinned runtime and checks ELF/target artifacts | Partial; CI is not a gameplay test |
| M1 | Owner ELF PT_LOAD, entry OPD/TOC, TLS and imports are parsed; selected game folder is indexed | Partial; reproducibility is CI checked, complete PRX coverage is not claimed |
| M2 | Full PPU lift is compiled and registered; native dispatch reaches the ELF entry | Partial; indirect-call/TOC coverage is not validated end to end |
| M3 | Four SPU images are registered | Partial; DMA/SPURS execution and RPCS3 cross-check are not demonstrated |
| M4 | Native iOS app, runtime and selected-folder VFS initialize without bundling game data | Partial; guest process boot must continue beyond CRT and perform guest I/O |
| M5 | Diagnostic Metal surfaces exist | Not passed; no Ascension RSX output is rendered through Metal/Vulkan |
| M6 | No gameplay or transition evidence | Not passed |
| M7 | Release label M7.72 is a software version | Not passed; criterion M7 requires measured, stable 30-fps gameplay |
| M8 | No fidelity-validated 60-fps/upscaling evidence | Not passed |

The version prefix `M7` in `M7.72` is not the same thing as passing criterion
M7. The immediate next device evidence after this boot-ABI change is a live
increase in native guest dispatches followed by positive guest `cellFsOpen`,
`cellFsRead` and byte counts. Only after those appear should PSARC parsing and
RSX/frame work be treated as the next blocker.
