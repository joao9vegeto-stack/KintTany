# M7.95: interpretador SPU para misses do WWS

O relatório M7.94 confirma que a entry AOT inicia e o jogo lê arquivos, mas não
confirma jobs do título nem comandos RSX: `draws guest=0` e `flips guest=0`.
As 60.329 admissões WWS não são jobs concluídos; os contadores genéricos de
job-chain cobrem outro caminho.

O launcher já define `SPU_INTERP_UNLIFTED=1`, mas o fallback completo do runtime
fixado estava condicionado a `!ctx->policy_mode`. Um miss de código no policy
WWS chegava primeiro ao microstep parcial. M7.95 mantém as rotinas estáticas e
os lifts PIC de bytes exatos na frente e, quando ambos falham, permite que o
policy WWS use `spu_interp_run_until_budget` para executar o código vivo no
Local Store. Cada chamada interpreta até 4.096 instruções, retorna ao
trampoline preservando estado e PC, e continua no próximo despacho. Isso limita
cada trecho do interpretador e evita crescer a pilha do host em um corpo longo.

Os cinco fragmentos anexados apontam para `LS=0x3FEC0` nos overlays 0, 226 e
229 e contêm sequências de stores de registradores. Essas sequências não
correspondem aos bytes do ELF fornecido; por isso o runtime não inventa uma
associação a uma rotina nativa. O caminho M7.95 executa esses bytes pelo
interpretador até alcançar um lift registrado, o retorno do drain ou o próximo
limite de 4.096 instruções.

## O que precisa ser confirmado no aparelho

O patch corrige o despacho do interpretador para misses do policy WWS. Ainda
não prova que o jogo chama o backend RSX nem que haverá um frame. A próxima
execução precisa mostrar código WWS avançando e, para sucesso visual, draws e
flips guest acima de zero junto de um vídeo com imagem do jogo. Se os contadores
continuarem zerados, o relatório deve localizar o primeiro miss seguinte; não
se deve tratar admissões de scheduler como execução de jobs.
