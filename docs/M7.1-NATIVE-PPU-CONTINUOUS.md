# AscensionRecomp M7.1 — continuous native PPU interpreter fallback, not AOT

## Physical evidence before change
NPUA80918 GOWA.ELF was imported **privately on device**:
- M6.7.6 48/48 PowerPC instructions, verified TLS.
- M7.0 native libAscensionPPUCore-ios-arm64.a embedded in IPA.
- Actual ELF loader returned 0, entry 0x00010410, TOC 0x0083F2B0,
  2 segments (8,694,360 file bytes), PRX NID 0x744680A2 recognized,
  native HLE TLS 0, r13=0x00A6F000.
- ar_run at guest entry returned -3 and unresolved PC 0x00010410
  because **zero game-specific AOT functions** are linked.
This is correct: loading an ELF does not produce signed ARM64 code.

## What is implemented
The signed IPA now embeds two additional ARM64 C objects:
ios/ARNativePPUContinuous.c and ios/ARLivePPUContinuous.c.
The first is a generic PPC instruction interpreter over the same
native ar_vm_* big-endian guest memory, with a bounded budget of
up to 8192 operations (iPhone test uses 4096). The second creates
a clean, separate guest process using the real native ELF loader,
ELF PT_TLS-derived entry ABI (r7 through r10 and page size r12),
native PPU thread identity, and the exact verified firmware import
table; it executes the **real guest CRT naturally** until an
explicit stop, rather than precalling TLS or fabricating an AOT
function registration.

Supported subset covers instructions proven in M6.7.6 (addi,
addis, ori, oris, lwz, ld, std/stdu, stw, relative branches,
rldicl, or, mflr/mtlr, mtctr/mfctr, blr, unconditional bctr/bctrl)
plus xori, xoris and andi. with CR0. Unknown instructions fail
closed at their exact guest PC. Import dispatch is restricted to
a verified sysPrxForUser NID 0x744680A2 and HLE bound to runtime.
Executable PT_LOAD ranges are checked for fetch and branch target.
Every fault reports PC, opcode, guest effective address, HLE count,
LR, CTR, r13, and number of successfully executed instructions.

Distinct outcome codes:
-1310 guest budget exhausted; -1311 unsupported opcode/ISA form;
-1312 unmapped or nonexecutable branch; -1313 memory access fault;
-1314 missing indirect branch/HLE/LV2; -1315 real HLE failure;
-1316 invalid ELF for decoder. Setup error is a separate code.

Critically, native ar_run AOT remains zero and AR_UNRESOLVED=-3.
**This is interpretation by a signed native ARM64 binary, not
static PS3→ARM64 game recompilation, not JIT, not gameplay**.
The goal is to get a longer real coverage trace and use the
first honest stopping reason for ISA/HLE implementation; actual
native AOT later requires privately lifting and signing code.

## CI
Synthetic ET_EXEC fixture:
- CRT forwards the real PT_TLS fields and calls the authenticated
  firmware HLE, showing actual r13 and a stop on next unknown word.
- Wrong import NID is rejected, no artificial HLE success.
- A separate synthetic executable region runs 76 guest NOPs,
  proving not limited to the previous 48-step interpreter.
- 64-step quota stops with a distinct budget status;
  unimplemented opcode and invalid ELF both stop safely.
- Existing M4/M5 RSX, M6.7.6 and M7.0 checks unchanged.
- App linked symbols are inspected for both native fallback APIs.
No commercial PS3 ELF/SELF, RAP, code bytes or license in CI or IPA.
