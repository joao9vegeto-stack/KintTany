# M8.13 — Generated WWS C8 interrupt stub, native AOT, no interpreter

## Device evidence, NPUA80918
M8.12 (report 20261024-225617) did not render. PPU AOT 3,780,577 calls; SPURS2 PM upper 343 calls, 343 native returns; WWS job chain 0; taskset runners 6 active and 0 returns; guest file reads 242; RSX draws 0. Crucially **1,382,478 SPU native misses**, first current opcode 0x20FF3800 at LS 0x3FEC0, image=6 resident overlay=0 LR=0x02CD8.

## Cause in source
The C8 WWS PM game-specific AOT (runtime/m789-c8-wws/spu_recomp.c, `wws_pm_c8d774_spu_func_00000A2C` / `00000A60`) builds an IRQ save routine at LS 0x3FEC0: 0x130=304 bytes, 76 stqa instructions writing r0..r75 into 0x3F9C0..0x3FE7F, followed by `bi $79` 0x35002780 at 0x3FFF0. The dual generator at 0xA90/0xAAC produces 76 lqa instructions for restore. The translator generated `wws_pm_c8d774_spu_func_0003FEC0` as a placeholder that only retries an indirect lookup of itself, without saving/restoring. M8.12 strict native mode prohibited the old ps3recomp microstep fallback; repeated no-lift is therefore expected. The observed stqa instruction decodes to r0, LS=0x3F9C0 (matches generator). Source differential of gowa-pc gowa-fixes and gow2-recomp confirms correctness of SPURS/RSX treatment but executable addresses cannot be imported from other games/versions.

## Implemented fix
- `spu_ascension_run_c8_generated_irq` (compiled into PS3Recomp runtime) checks image=6, policy mode, entry=0x3FEC0, 76 full expected instruction words (save base 0x20FF3800 or restore base 0x30FF3800, stride 0x201) and terminal bi r79=0x35002780.
- Native fixed-function 76-register store/load via `spu_ls_write128`/`spu_ls_read128` to exact LS range, then direct return via r79 to the already lifted C8 code. **Not an instruction interpreter**. No new guest instruction decoding loop or guest-code execution fallback.
- Preserve the original C8 AOT source byte-for-byte and its hash-verified manifest; the existing placeholder already dispatches to spu_indirect_branch, which intercepts this exact generated template before any PIC/interpreter fallback.
- Strictly refuse unknown opcode sequences. Count native saves/restores/rejects and report last target.
- Both runtime trees are checked; ARM64 runtime and final Mach-O linker must export the helper, metric API and the original C8 entry. Its original source manifest remains SHA-verifiable.

## Acceptance
Success requires an on-device report with nonzero C8 IRQ saves/restores, falling 0x3FEC0 AOT misses and later meaningful guest WWS jobs/FS reads/RSX draws. A compiled IPA alone does not prove pixels or fix every subsequent game issue. Keep all other branches untouched.

The M8.13 run 442 compiled and packaged a valid ARM64 IPA but the Actions result failed on a redundant demand for the C8 0x3FEC0 thunk as a public Mach-O symbol. Clang can inline this source-level function. Actual final binary contained _spu_ascension_run_c8_generated_irq and _spu_ascension_copy_c8_irq, and the original SHA-verified C8 source still has its dispatcher thunk. Remove the false final thunk-symbol gate, keep the runtime and final Mach-O checks for both native functions, and check the intact source instead.
