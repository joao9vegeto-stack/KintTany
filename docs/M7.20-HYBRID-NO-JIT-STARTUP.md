# AscensionRecomp M7.20 — Exit from one-IPA-per-PPC-basic-block treadmill

## Evidence from real M7.19 NPUA80918 iPhone report
- 1,418 original native ARM64 AOT entries linked.
- Native AOT dispatches 1,502, 91 distinct ARM64 entrypoints reached in that single initialization run.
- HLE executions 429 (unchanged since M7.17).
- First unresolved AOT entry 0x003C4FC4 with authentic executable PPC/BE words:
  `30C90004 7CC63B96 7CC639D6 7CC64810 30C60004 2C060000 41820008`.
- Decoded ISA includes addic, divwu (XO=459), mullw (XO=235), subfc (XO=8), cmpwi and conditional branch. Previous batch compiler rejected divwu/mullw, thus AOT expansion missed it even after 850 additions.
- No real Ascension RSX command stream, menu, textures, SPU gameplay or stable FPS established. 91/1,418 measures %linked entrypoints exercised in that run, **NOT** % of game completeness.

## Actual M7.20 implementation
M7.20 adds optional, strictly bounded signed C PPC interpreter ONLY for missing AOT entrypoints, to unblock/identify dynamic startup routes without compiling a new IPA per omitted basic block. It is **not JIT**, nor statically compiled ARM64 AOT and must never be counted as such.

1. All existing 1,418 AOT functions and ELF SHA-256 owner digest checks remain untouched. The AOT hash dispatcher has priority at each PC.
2. The authenticated user-selected ELF may be attached for fallback **only after** the existing original SHA-256 private AOT install and module registration succeeds. It remains owned by the file importer and is not embedded/uploaded.
3. On AOT miss, ar_m712_exec_window verifies PPC64/BE executable PT_LOAD and current guest executable word equals exact original ELF; foreign PRX and mutated code are rejected. The interpreter steps through supported fixed-point arithmetic, signed/unsigned comparisons, loads/stores, branches, LR/CTR calls and relevant remainder operations. Unsupported opcodes and undefined divide-by-zero fail closed.
4. Overall dispatch budget is 8,192 entries/steps, fallback per-run limit 2,048 PPC instructions, recursion depth still 64. Zero fallback steps if not explicitly attached. Guest MMU bounds enforced by existing memory bridge.
5. ar_aot_trace has independent fallback_steps, fallback_last_pc/opcode, unsupported_pc/opcode, fallback_step_limit fields. Native ARM64 AOT dispatches/unique counts are unchanged.
6. Native UI still has a SINGLE full-report/TXT export button, with a M7.20 hybrid execution section and honest failure reason -3 unresolved AOT, -12 unsupported PPC and -13 fallback bound.
7. Pure host C tests use only synthetic ELF with genuine PPC instruction *types*, not commercial game code, exercising ARM64 precedence, 7-opcode arithmetic sequence, BEQ, divide-by-zero, unknown ISA, budget, and attach/reset. No further Actions secret is necessary.

## Finish line for AOT and next gates
Do not wait for all functions in GOWA.ELF to be compiled. Use static AOT for stable hot paths and the interpreter for cold/unknown paths while growing ISA support based on measurable runtime failures. **AOT phase can be deprioritized when:**
- Guest entrypoint/startup reaches a persistent real game runtime after more than a bootstrap, rather than AR_UNRESOLVED, AR_PPC_UNSUPPORTED, memory or HLE failure; real PPU state, PRX imports and syscalls agree.
- Function/ISA profile identifies sufficient coverage for performance hotspots.
- Real SPU tasks, game file I/O, PRX/HLE and RSX FIFO commands are observed/handled, not just rendered via synthetic Metal tests.
- Only then profile 30 FPS frame time across CPU, SPU, RSX and Metal. 60 FPS/framegen remains a later contingent target.

This M7.20 build alone does NOT claim it has reached any of those gates. Only user iPhone TXT can prove how far the hybrid trace progressed. All changes remain strictly on AscensionRecomp, one commit/one push workflow unless an actual CI failure requires a correction.
