# AscensionRecomp M7.14 — validated native PPU continuation + offline batches

## Starting evidence (owner's iPhone, NPUA80918)

M7.13 executed 65 genuine ARM64 AOT entrypoints, returned AR_UNRESOLVED (-3) at 0x003C4DA4, authenticated full original GOWA.ELF, with native TLS/SYSUTIL and guest memory mappings. Original PPC BE executable words on device:

- `0x78840020`: `rldicl r4,r4,0,32` → zero-extend lower 32 bits.
- `0x907D0018`: `stw r3,24(r29)` → guest big-endian 32-bit store.
- `0x3C608000`: `addis r3,0,-32768` → 0xFFFFFFFF80000000.
- `0x93DD0010`: `stw r30,16(r29)` → guest big-endian 32-bit store.

These are copied *only* from the four user-reported authenticated instructions. The M7.14 native fragment is registered after the existing secret's 64 entries and the M7.13 one, and after the whole-ELF SHA-256 has matched. Registration checks the exact four PPC words in an executable ELF64/BE PT_LOAD. Memory writes use the guest runtime's range-checked `ar_write32`, abort on faults, preserve CR/LR/CTR/XER, and then return `AR_TAIL` to 0x003C4DB4. The next address is **not** assumed to be valid native ARM64. New expected linked entries: **66**, awaiting iPhone proof.

## Replace one-address-per-build discovery with batched evidence

`ar_m714_frontier_inventory` performs a read-only inventory of **up to 32 original PPC instructions** beginning at the next unresolved guest PC. It stops on a branch or syscall opcode and checks executable, file-backed ELF bounds for each group. There is **no PPC interpreter**, JIT, fabricated path or execution of unknown bytes. The App's *Diagnóstico avançado* offers the inventoried PC/opcode pairs to copy. The primary status remains short.

A private offline owner-only planner is now included:

```sh
python3 tools/m714_owner_batch.py \
  --elf /private/GOWA.ELF \
  --pcs-json /private/frontier-pcs.json \
  --out /private/ppu-batches \
  --max-words 256 \
  --emit-private-aot
```

An example `frontier-pcs.json` is `["0x003c4db4", "0x003c4e40"]`. The tool accepts up to 8,192 **distinct** guest entry candidates, scans bounded executable ranges, and only sends a candidate to the existing static lifter if a supported terminator is found and the CFG/ISA is supported. Outputs include `batch-audit.json`, `batch-functions.json` and an optional private `PRIVATE-AOT/ascension_private_aot.c`. Unsupported code is rejected with a reason; it is **not** silently interpreted or linked.

**Important:** This is not an automatic replacement for the current 64-entry owner secret. The private batch source contains only accepted candidates. Before using a new secret, rebuild and validate the *complete* native entry set for the original game, including previous 64 entries, or maintain separately authenticated modules. The existing secret remains unchanged in M7.14. The user works on iPhone, so the on-device inventory is the immediate trace-collection channel; executing the offline builder later requires a private environment with the original ELF.
