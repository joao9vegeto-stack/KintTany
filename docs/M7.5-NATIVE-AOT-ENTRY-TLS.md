# AscensionRecomp M7.5 — Native AOT CRT execution without smoke contamination

## Why this is necessary

The signed AOT functions generated from a user's authorized PPC ELF must run
from a **fresh guest process-entry context**. The M7.0 diagnostic previously
ran an HLE TLS smoke call using that same `ppu_context`, setting `r13`,
`LR` and argument registers and consuming the TLS allocator before dispatching
the entry AOT function. That state is not the PS3's original entry ABI.

## Fix (generic, public, no game bytes)

- M7.0 continues to bind **only** the authenticated `sys_initialize_tls`
  import; missing HLEs still fail closed.
- With **zero** signed AOT game functions, M7.0 preserves the legacy smoke
  in a **copy** of the CPU context and its preexisting diagnostic outputs.
- With **at least one** signed AOT function linked, the smoke is **skipped**;
  guest PPU entry starts with its real process-entry registers and
  `r13=0`. Native AOT calls the authenticated HLE itself, if supported.
- `out[5]` counts registered native functions; `out[6]` reports the
  real native dispatch return; `out[7]` identifies the first missing
  native function/import; `out[12]` reports the actual AOT `r13`.
  The bit for the legacy HLE smoke remains off in the AOT path.
- The public Actions compiles a synthetic native guest entry, confirms
  that `r13` is initially zero, invokes actual TLS initialization through
  `ar_guest_call`, verifies the resulting `r13`, checks that ELF digest
  mismatches are refused, and ensures an unbound PRX import returns
  `AR_UNRESOLVED` rather than falsely succeeding.
- M7.4 tests already demonstrate native AOT functions translated from
  synthetic PPC, and M7.5 tests the subsequent native runtime ABI.

## Real game status

The user's earlier private M7.5 package translated three real functions
from their NPUA80918 copy: `0x10410`, `0x10534`, `0x531cac`.
That file contains copyrighted game-derived code and is not in this
public commit. Its host-native trace reaches missing `0x531a74`.
**This public build has game AOT count 0 and is not gameplay.**

To produce an IPA with these private ARM64 functions, compile/link the
game-derived source *before* iOS code signing using the existing
`ASCENSION_PRIVATE_AOT_C` switch in a restricted runner. Do not rely on
deleting public commits or artifacts to retract code already exposed.
