# AscensionRecomp M2.5 — Canonical PPU ABI and bounded guest dispatch

**Fixed real integration blocker.** The M2.3 experimental PPU lifter generated
a simplified context incompatible with the actual PS3Recomp PPU context:
upstream places FPR and aligned AltiVec VR after 32 GPR, then CR/LR/CTR/XER.
Passing the old pointer to the full runtime would misread/corrupt registers.

The lifter now includes the pinned upstream `ppu_context.h` and aliases it
to `ppu_ctx`, preserving the full data layout. Host-only Python unit tests
use a synthetic mirror; **the GitHub Actions separately compiles and runs the
same dispatch smoke against the ORIGINAL pinned upstream header** and asserts
exact offsets, size and LR/CTR/CIA consistency.

The new single-thread smoke bridge offers:
- Bounds-checked guest memory and big-endian 8/16/32/64 access.
- Explicit registry of PPU function entries with duplicate detection.
- Nested guest calls and tail dispatch, both under a shared step budget.
- Error code plus missing function address; never fake success on absence.
- Validation of LR save/restore by generated PowerPC synthetic functions.
- iOS arm64 Mach-O compilation of bridge and synthetic guest objects.

**Not a playable IPA.** This bridge is single-threaded, not the full PS3
runtime, HLE/SPURS/SPU/RSX/VFS or PS3 memory mapping. Commercial GOWA.ELF,
SELF, RAP and lifted code remain private and OFF the GitHub Actions.

Next: actual ELF load image map, OPD import resolution, and PS3Recomp
full-lifter function boundary/indirect dispatch integration.
