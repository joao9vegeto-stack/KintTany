# AscensionRecomp M7.6 — native AOT basic-block dispatch

The public iOS runtime already supports authentic AOT functions through the
`ar_register` and `ar_run` APIs. A translated PowerPC function may return
`AR_TAIL` with a new guest `cia` when the translated control flow crosses
a compiled code block. M7.6 adds a synthetic regression that proves the native
dispatcher follows chained `AR_TAIL` transfers, authentic import binding,
HLE return, and honest `AR_UNRESOLVED` reporting. This is native C execution,
not PowerPC interpretation.

The app's PPU report distinguishes the real AOT registration count and
last missing guest native block from the independent interpreter diagnostics.
Build number 76 preserves the original test tools.

## Verification outside public CI

Using the exact owner-supplied NPUA80918 PPC64 ELF, an offline translator
produced native C covering **169** PowerPC instructions in **six AOT entries**:
the three original entry/CRT routines and three separately compiled
basic blocks of the next startup routine. The validated host-native path
successfully executes one TLS HLE and then reports the guest PRX import
stub at `0x00669A84` as not yet resolved. That imported service was already
identified in M7.3 as `sysPrxForUser` NID `0x2F85C0EF`.

The translated source and iOS ARM64 object are maintained in a separate
user-local package. Neither game-derived source nor the original executable
is included in this public commit or Actions artifact.

**This public build remains an iOS diagnostic IPA with game AOT=0.**
The host-only result does not prove iPhone execution of game ARM64 code,
complete game semantics, SPU support or gameplay.

## Regression criteria

- AOT chain: PC 0x10000 -> 0x10010 -> 0x10020 -> authenticated test HLE.
- Unknown branch: AR_UNRESOLVED with exact guest PC 0x10048.
- Native AOT state reset after VM shutdown.
- Legacy M6/M7 PPU diagnostic preserved for on-device comparison.
