2) NOVA CORREÇÃO DE CONTROLE NATIVO M7.68
arquivo: runtime/ppu_bridge.c + ppu_bridge.h
- O dispatcher atual usa lookup AOT, então fallback a tabela PRX/HLE.
- Descoberta de fluxo real: AR_TAIL de uma função AOT para o stub
  importado entrava no HLE mas, após HLE retornar AR_OK, o dispatcher
  terminava a rodada. Um BL PPC deve CONTINUAR a execução no endereço
  LR nativo do guest (ex. 0x0053950C), se a origem veio de AOT_TAIL.
- Mudado: em AOT_TAIL->import HLE, registrar lookup e handler HLE
  separadamente do lookup AOT. Após HLE bem-sucedido, preservar TOC e
  registros guest, buscar/continuar pelo LR através do dispatcher ARM64;
  na falta de handler para LR, parar nesse LR, sem fabricar sucesso.
- ar_guest_call() direto (chamada aninhada originada em C AOT) conserva
  seu contrato: retorna AR_OK ao C native caller, não duplica o retorno
  via LR. Uma flag local from_native_tail distingue os dois caminhos.
- O primeiro erro profundo (PC, LR, CR, TOC, CTR, r1/r3) não é sobrescrito
  no desenrolar de chamadas nativas com erro.
- Novo trace M7.68 (log + AOT_TRIAGE_JSON): n.º HLE lookups vindos de
  TAIL, handlers encontrados, retornos ao LR, último LR, ARM64 no
  retorno, origem por TAIL e profundidade. Medições separadas, jamais
  contar HLEs como funções AOT. Não adicionar handler nativo fake ao stub.
- Testes host reproduzem: AOT BL->stub HLE->LR->próximo native,
  chamada direta aninhada, destino LR sem ARM64 -> falha correta; 0
  instruções PPC interpretadas. Testes host são sintéticos, não
  demonstram execução no iPhone.
