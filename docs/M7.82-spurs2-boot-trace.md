# M7.82: SPURS2 boot path and honest PC telemetry

## What the 7.81 capture showed

The value `0x003C4FA4` is the last sampled backedge of the binary-search loop in `func_003C4F98`; it is not the instruction currently executing. The loop count stopped changing while AOT calls continued. The later addresses `0x006698FC`, `0x00669934` and `0x00669A14` are import stubs for `sys_lwmutex_lock`, `sys_lwmutex_unlock` and `sys_lwcond_wait`.

The actual missing service in that capture was `cellSpursCreateTaskset2` (`0x4A6465E3`), called from guest return address `0x003E1E8C`. The report showed no guest draws or flips. The Ascension PC port's taskset milestone explains why returning `CELL_OK` from this import cannot start the game: Taskset2 must be 0x2900 bytes, own two LV2 event flags, and be scheduled across sibling tasksets when SPU jobs create their next phase.

## Runtime changes

- Applied the Ascension PC port's SPURS2 initializer, LFQueue producer and taskset scheduling patches to both pinned PS3Recomp trees used by the iOS build.
- Added Task2 create/join/try-join, taskset address/destroy and workload-flag services to the generated all-module HLE table.
- Added the game's SDK CellSyncLFQueue layout and host Edge Zlib inflate path. The inflater honors the output skip, truncated chunk reads, request counter and event flag used by the WAD streaming path.
- Added guest range checks around LFQueue buffers and the Edge request before touching the 32-bit guest address space.
- The launcher enables these two game paths before runtime start: `PS3_LFQUEUE_SDK_LAYOUT=1` and `PS3_EDGE_ZLIB_HLE=1`.
- The runtime report now distinguishes a sampled AOT function entry from a live PPC instruction PC and shows recent AOT samples, recent HLE calls, and recent unresolved imports with their guest LR.
- A second launch now reports live counters instead of reusing the previous run's final snapshot.
- Added `AJUSTES` with Metal drawable scaling (0.5×, 0.75×, 1×) and 30/60 Hz guest VBlank cadence. Drawable scaling affects only presentation pixels; VBlank cadence is not a promise that the game will produce that FPS.

## Verification and current limit

The patched SPURS, SPU workload, and event sources pass local C syntax compilation; the HLE generator emits the expected NIDs, including `0x4A6465E3` and `_cellSpursLFQueuePushBody`. The Apple ARM64 build and link are verified by the branch Actions workflow.

This source change does not claim a first game frame. A physical iPhone run is still required to confirm that the new taskset and asset path reach guest RSX draws and a presented flip. If another import blocks next, the live unresolved-HLE ring will show the NID and guest LR instead of leaving `0x003C4FA4` looking current.
