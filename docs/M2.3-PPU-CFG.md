# AscensionRecomp — M2.3 experimental PPU CFG lift, 2026-10-15

## Technical deliverable (game remains private)
Generic `tools/ppu_cfg_lifter.py` translates an explicitly bounded subset of PPU64 instructions to compilable host C. Internal direct branches become labels; branches exiting the function set `cia` and request tail dispatch. Conditional branches evaluate guest CR/CTR; linked calls set LR, invoke the caller's callback; bclr/bcctr and 64-bit rotates, compare and addc are included. Unsupported instructions FAIL CLOSED, never silently NOP.

Tests run generated C on a host compiler, with synthetic inputs only, and
cross-compile a synthetic PowerPC fixture into Mach-O arm64 for iOS.

## Limitations and next gates
- This subset lacks full FP/AltiVec, an interpreter fallback and an iOS runtime integration. CALL/TAIL dispatch and memory callbacks must be implemented/validated with guest thread state; their current contract is only a test scaffold.
- Even an accepted candidate may contain a data region that happens to decode as instructions. The tests establish limited semantics, NOT equivalence for the entire PS3 game.
- Must differential-test against RPCS3 for live guest state, wire PPU/SPU/Cell SPURS, VFS, HLE NIDs, and RSX backend, then package/sign a real IPA.
- Next: prioritize SPURS/DMA, HLE guest memory callbacks and floating/vector instructions, and compare full upstream ps3recomp lifter as soon as its source is available to the private environment.
- One change -> one branch-specific workflow only, never touch main or PsTJon/KosmicKrisp.
