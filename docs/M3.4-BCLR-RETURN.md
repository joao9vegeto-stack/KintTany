# AscensionRecomp M3.4: PowerPC conditional BCLR return correction

Generic bug fixed: a conditional, taken BCLR instruction (e.g. beqlr)
with LK=0 must return from the guest function to LR. The previous
implementation erroneously tried to tail-dispatch to LR unless BO
indicated an unconditional branch, breaking calls to mid-function
guest return addresses.

Two synthetic C execution tests cover taken and not-taken conditional
BCLR. Unknown PPC opcodes continue to fail closed.

Private test (not part of GitHub Actions):
- A 53-instruction PowerPC memory-fill routine in the user's
  legitimately decrypted game executable at 0x52E180 was lifted.
- The compiled function matched `memset` in 9,984 independent cases
  across 39 sizes, 16 alignments and 16 byte values.
- After adding it to the PRIVATE game startup probe, the first
  unresolved address moved from 0x52E180 to 0x455F9C.
- The game ELF, license, generated game C and game-derived objects
  are not in this commit or CI.

This proves a narrow semantic regression fix and a further partial
guest startup step; it is NOT complete game boot, GPU, SPU or IPA.
