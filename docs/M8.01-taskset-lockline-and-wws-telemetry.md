# M8.01: protect SPURS taskset updates and measure real WWS work

## Finding

The M8.00 report showed 82,184 workload-policy admissions but zero guest draws
and zero presented flips. Its “job-chain” counters instrument a separate API;
they did not observe the SPURS WWS taskset scheduler, so zero there did not mean
that no taskset work had been submitted.

The pinned runtime updated taskset signal words and ready/pending/enabled bytes
with unsynchronized read-modify-write operations. Those locations share a
128-byte reservation line with the SPU task library's GETLLAR/PUTLLC updates.
A task exit could therefore write an old byte back over a task created or
signalled by an SPU. The Ascension PC port fixed both the signal-bit update and
the task-scheduler byte clears after observing a missing next-phase task and a
frozen level load.

The comparison used both requested references. [gowa-pc](https://github.com/RichardFontoura/gowa-pc)
documents the PPU/SPU/job-module lift pipeline. The concrete lock-line fixes
are recorded in [gow-ascension-pc patch 0015](https://github.com/arnaldolima1/gow-ascension-pc/blob/main/patches/ps3recomp-0015-taskset-bitset-lockline.patch)
and [patch 0037](https://github.com/arnaldolima1/gow-ascension-pc/blob/main/patches/ps3recomp-0037-taskset-bitset-lock-rejoin-call.patch).

## Change

- Protect the shared taskset signal-bit read-modify-write with the lock-line
  lock, using raw big-endian bytes and notifying SPU reservation holders.
- Protect the scheduler's ready, pending, and enabled byte clears with the same
  lock-line protocol.
- Add direct counters for taskset registration, task exits, ready candidates,
  valid task ELFs, requeue attempts/acceptance/failure, async task starts,
  image load/reuse/failure, runner returns, and active workers.
- Label the old job-chain API counters separately in the report so they are not
  mistaken for WWS taskset activity.

The patch is applied to the pinned PS3Recomp checkout by
`tools/m801_taskset_runtime.py`; no game ELF or game archive is included.

## Verification

`tools/test_m801_taskset_lockline.py` compiles the exact patched operations and
stresses 50,000 concurrent SPURS signal updates plus 50,000 task-exit/task-create
updates. Both complete without lost bits. The iOS workflow also verifies the
new runtime metric symbols in the linked app.

This regression test proves the host-side lock protocol. A physical iPhone run
is still needed to establish whether the change reaches the first guest draw
and flip; the build must not report a rendered frame until those counters are
positive.
