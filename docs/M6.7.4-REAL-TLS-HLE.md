# AscensionRecomp M6.7.4: real bounded TLS initialization

## Device evidence (NPUA80918)
M6.7.3 reached PPU instruction 39 and stopped on an invalid
bctrl destination 0x39800000. A checked read from the actual
ELF matched import sysPrxForUser/NID 0x744680A2, which is
sys_initialize_tls. Source code at the guest trampoline is NOT
a function descriptor; the pointer was being interpreted
incorrectly as one.

## Implementation
M6.7.4 introduces an optional import-aware PPU48 entry point.
Legacy entry points continue to reject the same invalid CTR
rather than invoking firmware HLE. The new entry point verifies
the imported stub address, module name, NID and two guest words
before dispatching exactly sys_initialize_tls.

The real gpr3..gpr6 supply thread ID, TLS template address,
file size and total memory size. Only a nonzero 32-bit main
thread ID, mapped source, currently unset r13 and a
file_size <= mem_size <= 16384 are accepted. Guest template
bytes are copied with the existing checked ELF/shadow reader,
remaining TLS bytes initialized to zero in a private guest
memory buffer (64KiB at guest VA 0x0E000000). r13 is set to
0x0E007000, ABI gpr3 is set to zero, original TOC restored,
and control resumes at the caller after the bctrl.

TLS reads and writes are checked within the private guest
region. The emulator does not jump to the host pointer and
does not allow arbitrary HLE calls. Errors remain fail closed:
-1011 invalid TLS params, -1012 already initialized,
-1013 template read invalid. Other unbound stubs still -1007.
The report exposes the success state independently of the
later PPU opcode status. This is early CRT only, not game boot.

## Validation
The synthetic host fixture checks a verified import with
nonzero guest thread ID and a copied/zeroed TLS image,
restored control to the guest caller, a wrong NID being
refused, invalid TLS length, unmapped template, and the
legacy API still returning -1007.
Do not include game ELF/SELF/RAP in CI or IPA.
