# AscensionRecomp M7.2 — generic PowerPC comparison/CR/branch ISA

## Actual NPUA80918 iPhone evidence
M7.1 successfully loaded the private ELF into native PPU guest VM,
executed 51 guest PPC instructions naturally, and invoked a genuine
sysPrxForUser / sys_initialize_tls NID 0x744680A2 HLE. At guest
PC=0x000105A8, instruction 0x7FBF4040 stopped -1311.

This instruction is **cmpld cr7,r31,r8**:
- 31 primary opcode, XO=32 (compare logical), BF=7, L=1,
  RA=31, RB=8, Rc=0 and reserved bit=0;
- compare 64-bit values as unsigned, write LT/GT/EQ/SO to CR7.
A patch for this exact address alone would not be sufficient because
other compare forms and conditional branches depend on CR fields.

## Generic, data-driven implementation
The signed ARM64 interpreter now supports:
- cmp/cmpl register forms (primary 31, XO 0/32), signed/unsigned,
  32/64-bit; cmpi/cmpli immediate forms (primary 11/10), including
  correct sign- and zero-extension and reserved-bit checks.
- exact CR nibble update (BF0..BF7, LT/GT/EQ and XER SO);
  comparisons preserve all other CR fields.
- bc/bcl: BO/BI conditional CR comparison, CTR decrement/test,
  AA and LK even on a not-taken branch, branch destination validation.
- bclr/bclrl: conditional CR/CTR and LR target (with old LR snapshot
  before LK). bcctr/bcctrl: conditional CR and CTR target, rejects
  invalid decrement-CTR form as ISA failure. Maintains existing
  authenticated sys_initialize_tls native HLE call path.
- non-executable targets and unsupported opcode forms fail closed.
No guest bytes are treated as native host instructions.

## Synthetic CI
The new ELF synthetic host fixture deliberately runs exactly the
real-world opcode 0x7FBF4040 plus signed and unsigned comparisons in
distinct CR1/CR2/CR3/CR4/CR6/CR7 fields. It verifies:
- branch taken by CR7 LT and CR1 EQ independently;
- CR2 GT after cmpldi and CR3 non-EQ on bne;
- signed negative and unsigned 64-bit -1 comparisons differ;
- a CR branch not taken falls through to the sentinel opcode;
- bdnz/bdz decrement/test CTR correctly;
- malformed comparison and illegal conditional-CTR branch are rejected;
- bclr and bcctr conditional branches use verified guest LR/CTR;
- budget exhaustion and executable-target validation are preserved.
Tests use no PS3 commercial game/SELF/RAP bytes.
