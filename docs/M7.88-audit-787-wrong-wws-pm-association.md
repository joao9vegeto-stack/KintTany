# M7.88: M7.87 stops before title job dispatch

## Device evidence supplied for M7.87

The log reports 47 guest `cellFsOpen` calls (37 successful), 244 `cellFsRead`
calls and 11,551,674 bytes read. SPURS saw 18 workloads; all reference guest
EA `0x007A7B00`, size 12,288, fingerprint `C8D774963A96DCF2`, image 5. The
WWS policy admission counter reached 3,444,813. Title job-chain requests,
resolved or missing job lifts, runner returns, active jobs, guest draws and
guest flips all remained zero. The supplied video shows the launcher/report,
not a game frame.

## First source-level stop in the path

The previous registry associated the runtime C8 fingerprint with
`wws_pm_npua_spu_func_00000A00`, although that native lift was generated from
the NPUA image fingerprint `CE052ACDA7412063`. The two fingerprints identify
different byte sequences; no semantic-equivalence check or matching runtime
bytes were available to justify the alias.

The registered NPUA entry at `0xA00` immediately executes `stop 0x94`. In this
runtime, `spu_stop` records the stopped state and returns to the host. The
SPURS policy wrapper reports failure (`-2`) unless its exit-to-kernel callback
ran. The worker ignores that return code, releases its slot, and admits the
same WWS workload again. That is consistent with millions of admissions while
the guest selector never calls the title's job-chain APIs. The earliest proven
break is therefore the mismatched WWS PM association and premature stop at
entry `0xA00`, before job dispatch. No GCM/RSX submission is evidenced yet, so
changing the Metal renderer would not address this first stop.

## M7.88 patch

- Keep only the `CE052ACDA7412063` NPUA PM associated with its NPUA-generated
  lift. The C8 runtime PM now fails closed instead of entering unrelated code.
- When SPURS resolves a PM that the native registry does not know, save that
  exact requested guest byte range once as
  `Documents/AscensionSPU-…/spupm_<fingerprint>_<size>.bin`. The existing
  export action shares the captured file. This is input for an exact PS3Recomp
  lift; it is not treated as a completed job.
- Show the latest guest filesystem path from the existing `last_path` field in
  the live report; no file history is collected.
- Invalidate the cached M7.87 native archive attestation so the iOS artifact
  cannot silently retain the C8-to-NPUA alias.

## What remains to get the first frame

M7.87 did not reach any job-chain API or guest RSX draw/flip. M7.88 corrects
the false association and captures the PM needed to build a matching native
lift, but the captured C8 image has not yet been lifted, linked, and run on the
iPhone. Therefore this patch does **not** claim to eliminate the whole frame
blocker or to render a frame. After installing M7.88, run the game once and
export the requested `spupm_…bin`; that exact file is required to add and
verify the next native PM lift. Only a device report with guest draw > 0 and
presented guest flip > 0, plus a video of the game image, establishes success.
