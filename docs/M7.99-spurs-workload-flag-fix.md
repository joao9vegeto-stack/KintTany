# M7.99: SPURS workload-flag parity with the US PC port

## Audit of M7.98

The attached M7.98 capture still reports zero guest draws and zero presented
guest flips. Its 83,769 WWS PM admissions are scheduler-slot claims, not proof
that an SPU job completed. The report does not record a call to
`_cellSpursWorkloadFlagReceiver`, so this audit does not claim that the flag
path was the observed cause of this particular stop.

The M7.98 code change only affects `NV4097_GET_REPORT` (`0x1800`). The capture
does not say whether the guest reached that method; with no guest draws or
flips, it cannot establish that this RSX change ran. This is why M7.98's
unchanged screen was not evidence that the first-frame blocker had moved.

## Confirmed code divergence

The local `gowa-pc` reference uses the `RichardFontoura/ps3recomp` `gowa-fixes`
runtime. Its `spurs_initialize_common` initializes the SPURS workload-flag
value at `CellSpurs + 0x6C` to `0xFFFFFFFF` and the receiver at `+0x77` to
`0xFF` (NONE). The scheduler checks for a zero flag assigned to the current
workload, consumes it, and treats it as a kick.

The iOS patch already implemented the two guest APIs, and its receiver HLE
expects `+0x77 == 0xFF` before assigning an owner. However, its initializer
set `+0x60` to all ones and left `+0x6C` and `+0x77` zeroed by `memset`. As a
result, the first `is_set` call sees receiver `0`, returns `BUSY`, and the
scheduler never consumes a workload flag. This is a real SPURS HLE mismatch
against the US port, independent of the launcher and Metal view.

## Functional change

- Initialize the actual flag value and the receiver sentinel at `+0x6C` and
  `+0x77`.
- Consume a zero flag under the SPURS lock-line lock and include it in the
  matching workload's scheduling kick, following the US runtime.
- Require the generated runtime patch to contain this path, and require the
  final ARM64 Mach-O to retain the scheduler function symbol.

The PPU AOT catalog and the SPU interpreter are separate from this fix: the
M7.98 build already links 29,849 PPU AOT functions, the NPUA/C8 WWS lifts, and
`spu_interp_run` into the IPA. The iPhone report proves PPU AOT execution and
C8 PM admissions, but it does not prove that the interpreter fallback ran or
that a WWS game job completed.

## Limit of this result

This fixes an independently confirmed SPURS correctness bug and produces an
M7.99 IPA for a device run. It does not prove that the game called the workload
flag API, nor that it is the last blocker before RSX submission. Success still
requires a device capture with guest draw > 0, presented guest flip > 0, and a
video of the game image. If those remain zero, the next blocking point must be
identified from the active SPU job/PC state; M7.98's scheduler-admission
count is not a substitute.
