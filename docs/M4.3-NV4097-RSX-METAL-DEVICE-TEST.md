# M4.3 — Validate NV4097 register-file → RSX engine → Metal → iPhone

The user's M4.2 iPhone screenshots show 1, 2, 3, 4, and 60 successful
on-device color-frame submissions, alternating blue, green, purple.
**That proves repeated Metal command-buffer presentation but NOT
60 FPS, the PS3 command pipeline or any game graphics.**

M4.3 preserves a single direct-Metal BLUE reference frame when the app
opens. After each tap, the application now emits synthetic PS3 NV4097
register writes to the pinned rsx_draw_engine_method API:

- Configure local RSX A8R8G8B8 framebuffer, clip, pitch and display buffer.
- Set guest SET_COLOR_CLEAR_VALUE and trigger CLEAR_SURFACE RGBA.
- Require pinned backend's debug color latch to match expected ARGB.
- Emit driver flip 0xE944 through same RSX dispatcher.
- Fence GPU command queue and sample actual center pixel via
  rsx_draw_engine_readback_center.
- Only show success when expected and readback ARGB match EXACTLY.
  Otherwise report -1 (RSX engine unavailable), -2 (clear not consumed),
  -3 (GPU pixel mismatch), with expected and observed values.

The reference and RSX paths are explicitly distinct. A Metal clear
that only paints the external UIView is NOT an RSX pass; the second
mode goes through rsx_dispatch, rsx_draw_engine, the renderer's
clear_color/present methods and host Metal. A mismatch now becomes
diagnosable on the user's actual device.

A title PPU/SPU FIFO and shaders are NOT involved. Only synthetic
register values are used in this diagnostic; the commercial God of War
Ascension executable, license and assets remain private and off CI.

Success would prove a clear/flip RSX path on-device; it does NOT
prove correct vertex fetch, texture sampling, ZCull, shaders,
complete game boot, stable 30 FPS or 60 FPS.
