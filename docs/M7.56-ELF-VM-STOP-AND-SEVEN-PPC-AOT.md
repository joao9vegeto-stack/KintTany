# AscensionRecomp M7.56 — host fallback counter was NOT a guest instruction

## Verified physical baseline
M7.55 on iPhone: owner SHA-256 `4bf75c897b82d1beb25514cbadaff3d03e1b0c7bf849fa5d289be4f9183462b5`; 7696 linked AOT, 91 unique executed, 1502 ARM64 dispatches, **0 PPC interpreted**, guest -3 PC 0x003C4FC4, last AOT 0x003C4FB4, `opcode=0x00000000` (old report). Guest sys_fs_open/read=0.

## Root-cause audit before touching the translator
The `opcode` field of `ios/ARProbeApp.m` was populated from `measured.fallback_unsupported_word`. Under `ASCENSION_NATIVE_ONLY`, the fallback was removed from the final Mach-O, and the fallback counters were zero. Thus the zero was a **telemetry source mix-up**, NOT observed zeros in guest RAM.

The local canonical `GOWA.ELF` (8,717,136 bytes) was independently inspected:
- `PT_LOAD` 0: `p_vaddr=0x00010000`, `p_offset=0x0`, `p_filesz=0x0080E468`, `p_memsz=0x0080E468`, `p_flags=0x400005` (execute bit present).
- `pc=0x003C4FC4`, `delta=pc-p_vaddr=0x003B4FC4`, `file_offset=0x003B4FC4`.
- Original BE bytes at that offset: `30 C9 00 04 7C C6 3B 96 7C C6 39 D6 7C C6 48 10 30 C6 00 04 2C 06 00 00 41 82 00 08`.
- No guest RAM byte dump was present in the M7.55 TXT, so comparing RAM with ELF in **that historical execution was impossible**. Loader `runtime/elf_image.c` nominally copies `p_filesz` from `d+p_offset` to guest virtual `p_vaddr`. It does NOT prove what was in the RAM at the moment of the physical M7.55 stop.
- New `ar_m756_capture_stop` samples the real guest VM before shutdown using `ar_vm_read_bytes` and computes ELF offset from PT_LOAD; explicit success/error/mismatch, ELF and guest bytes. TWO samples: fixed 0x003C4FC4, plus new unresolved PC. The report must show `NÃO MEDIDO` if guest memory unavailable.

## Actual seven original PPC instructions and AOT semantics
- 0x003C4FC4 `30C90004` addic r6,r9,4 (64-bit, XER.CA)
- 0x003C4FC8 `7CC63B96` divwu r6,r6,r7 (unsigned low word, divide-by-zero FAIL CLOSED)
- 0x003C4FCC `7CC639D6` mullw r6,r6,r7 (signed low word, PPC64 sign extension)
- 0x003C4FD0 `7CC64810` subfc r6,r6,r9 (XER.CA no borrow)
- 0x003C4FD4 `30C60004` addic r6,r6,4 (XER.CA recomputed)
- 0x003C4FD8 `2C060000` cmpwi cr0,r6,0 (signed low word, XER.SO sticky)
- 0x003C4FDC `41820008` beq cr0,0x003C4FE4, otherwise 0x003C4FE0.

`runtime/ppu_m756_native_divloop.c` uses these original seven instructions as hard verification across two executable ELF windows and matches each guest-memory word before ARM64 registration. It executes the block as **a single compiled entry**. The native-only dispatcher remains strict; neither branch successor has been newly translated merely because an address is known. A new unsupported PC can be encountered immediately on either successor.
