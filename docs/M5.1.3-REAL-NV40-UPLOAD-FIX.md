# M5.1.3 — iPhone video findings and deterministic fix

The iPhone M5.1.2 video shows two failures -104 (LINEAR and SWIZZLED);
guest draw count 0, Metal encoded guest TEX0 count 0, four FFFFFFFF
readback pixels. M5.0.4 shader compilation and prior M4.x texture/geometry
diagnostics still succeed on hardware.

Root cause confirmed by pinned upstream dispatcher: NV4097_SET_TRANSFORM_PROGRAM
is a FOUR-LANE 0x0B80..0x0B8C window and advances the instruction slot only when
lane3 is written. M5.1.2 incorrectly sent every word to method 0x0B80,
never forming a complete two-instruction VP in rsx_dispatch.vp. Fixed by
sending + ((i & 3u)*4u) for each of eight words; host runtime regression
compiles upstream rsx_dispatch.c and verifies the exact 8 encoded words.
Also fixed FP program's location flag: low bits 2=MAIN vs 1=LOCAL for the
guest program stored at 0x002B0000. A new on-screen readout shows whether
guest shader residency is true, VP instruction count, FP byte size, and
the actual FP register value for follow-up root cause if a pipeline fails.

**Device validation required:** M5.1.3 is only build-proven by GitHub CI.
Tap M5.1 DRAW RSX TEX0 twice (linear, swizzled); require 4 distinct colours,
positive guest draw and Metal encoded TEX0 counts; after that verify
M4.10 cache twice. Capture full screen. Diagnostic only; still no title boot,
