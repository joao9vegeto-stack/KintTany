# M7.3: Identify authentic second PRX import at real Ascension stop

## Verified device evidence from NPUA80918
The M7.2 iPhone run advanced from 51 to 108 *real interpreted*
PowerPC instructions, preserving the first native sys_initialize_tls
HLE with r13=0x00A6F000. It stopped at guest PC 0x00669AA8:
opcode=0x4E800421 (bctrl), CTR=0x39800000, LR=0x00669AAC,
error -1314, no unsupported opcode and no invalid guest memory.
This is compatible with an unhandled PRX trampoline but its
library/NID cannot be proven from the existing public report.

The M7.2 engine recognizes only the previously proven
sysPrxForUser NID 0x744680A2 / guest stub 0x00669C0C.
A second imported stub therefore fails safely at -1314.
Blindly mapping that new bctrl to sys_initialize_tls, or returning
an arbitrary success code, would corrupt the guest process state.

## New read-only evidence, no policy bypass
The M7.3 native interpreter still reaches the same exact guest
PC naturally; only when -1314 happens on exact bctrl does
ios/ARLivePPUContinuous.c inspect live register r12:
- exact failing guest PC, r12, CTR, TOC/r2, r0, args r3-r6;
- PRX libstub lookup of that specific 32-bit aligned r12 guest VA;
- actual library name and NID, number of imports and libraries;
- file-backed executable PT_LOAD validation of both code words;
- expected first word matching CTR, second word matching TOC;
- a strict bitmask for each of four authentication checks.
The ELF stays local on iPhone. Only bounded register and PRX
metadata, not executable bytes or private game files, is copied.

Unknown NIDs remain -1314, even if all metadata matches.
No HLE implementation is guessed; no guest code made executable
on the host; the existing M7.1 ABI and M7.2 comparisons stay intact.

## CI
A synthetic PS3 ET_EXEC with two imports tests a legitimate first
TLS HLE followed by a DIFFERENT, unknown NID 0xABCDEF01. It
proves the exact second stub is identified, both code words match,
library metadata is returned, and execution remains -1314.
Negative tests cover a mismatched PRX stub pointer, non-executable
data pointer, invalid evidence buffer, and identical original
M7.1 fail-closed semantics. All prior CPU, RSX/Metal and packaging
tests remain active.
