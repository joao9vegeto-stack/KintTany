# M7.81: M7.80 boot diagnosis

## What the device capture proves

`Video7.80.mov` shows a live PS3Recomp entry, a configured title VFS, 28 successful guest file opens, 113 guest reads, and 2,641,929 bytes read from the selected game installation. The entry remains in `EXECUTANDO` while the capture shows zero guest RSX draws and zero guest flips. Metal initialization, vblank ticks, and FIFO worker activity are host-side work; they do not mean that Ascension rendered a frame.

The last unresolved HLE in the capture is `0xCE4374F6`. The pinned PS3Recomp NID database maps it to `cellGamePatchCheck`. Its default unresolved-import path returns zero, which reports success. That is the wrong result for this launch: the app boots from the user's disc-style `NPUA80918` folder and has no installed patch. The Ascension PC repository has a PS3Recomp patch for this exact title behavior: `cellGamePatchCheck` must return `CELL_GAME_ERROR_NOTPATCH`.

## M7.81 change

Before compiling either the iOS runtime archive or the game's generated NID table, the workflow patches the pinned PS3Recomp `cellGame` module with the disc-boot HLE and declaration. The M772 build now requires the generated table to bind `0xCE4374F6` to `cellGamePatchCheck`; its cache schema also changed so an archive built without the handler cannot be reused.

The launcher now displays monotonic elapsed time from the accepted tap on **Iniciar Ascension**, updates it during execution, freezes it when the guest worker exits, and includes it in the exported execution report and game HUD.

## Comparison with the reference ports

- **GoW2 macOS/iOS:** full native PPU and SPU recompilation, a real SPURS worker pool, guest RSX FIFO processing into Metal, and a configurable `PS3_PAD_AUTOSTART` path. The iOS app already links the PPU/SPU images and Metal worker, but the M7.80 capture had no guest draw/flip to feed that worker.
- **Ascension PC:** full PPU and SPU path, SPURS task scheduling, synchronization between SPU jobs and GCM, and RPCS3 RSX or live draw. Its milestones record fixes for `cellGamePatchCheck`, SPURS tasksets/event flags, and GPU/SPU frame synchronization. Those are runtime boot requirements, not launcher presentation details.
- **This iOS branch:** the M7.80 capture proves PPU AOT execution and real guest file reads, but not a menu or gameplay frame. The missing disc-patch HLE is now corrected. Any further missing HLE/SPURS service or guest RSX submission must be judged from a new device run; a CI build cannot establish that the game displayed a frame.
