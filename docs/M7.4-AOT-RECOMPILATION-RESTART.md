# M7.4 — Retomada verificável da recompilação AOT, NÃO interpretação

## Evidência real que motivou esta etapa
M7.3 NPUA80918 detectou bctrl em 0x00669AA8, import PRX real
sysPrxForUser/NID 0x2F85C0EF, r12=0x00669A84, validação 0x1F.
108 instruções foram **interpretadas**; a IPA assinada continha
**zero funções AOT específicas do jogo**. Não há boot nem imagem do Ascension.

## Entrega
- `tools/ppu_aot_build.py` utiliza o lifter CFG existente da M2 para
  gerar C nativo a partir de intervalos de funções de um ELF PPC64 real.
  Rejeita instruções não suportadas e faixas ilegais; registra rejeições.
  O código gerado é AOT, **não** um novo interpretador.
- A saída inclui `ascension_private_aot.c` e `aot-manifest.json`,
  com SHA256 do ELF e entradas realmente geradas. Material gerado a
  partir de executável comercial **NUNCA pode ser adicionado ao GitHub**.
- `ar_private_aot_install_sha256` só registra essas funções se a
  cópia importada coincidir byte-a-byte via hash SHA256 validado no
  próprio iPhone. Um ELF divergente impede o registro; não há bypass.
- O app iOS chama o instalador antes do despacho `ar_run`, quando
  um módulo AOT privado está linkado. Sem módulo, continua reportando
  fielmente AOT=0 e `AR_UNRESOLVED`. O fallback M7.1/M7.3 é preservado.
- `tools/build_ios_probe_ipa.sh` recebe `ASCENSION_PRIVATE_AOT_C`
  APENAS em ambiente privado; compila para arm64-apple-ios17.0 e
  linka no executável antes da assinatura. Sem essa variável, o
  Actions público mantém a IPA sem funções do jogo.
- Teste CI gera ELF PPC64 **sintético** com duas funções, recompila
  para C nativo, executa ambas no dispatcher C (uma chama a outra),
  exige valor real de GPR3=7, rejeita hash adulterado, compila objeto
  Mach-O arm64. Testes M4–M7.3 continuam.

## Execução privada — requer compilador com acesso autorizado ao ELF
Na máquina privada com Python e toolchain Apple, criar um JSON contendo
faixas verificadas (exemplo representativo):
```json
[{"start":"0x10410","end":"0x10444"}]
```
Não usar o exemplo sem confirmar os limites reais via CFG/ELF.
```sh
python3 tools/ppu_aot_build.py \
 --elf /private/GOWA.ELF \
 --functions /private/functions.json \
 --output-dir /private/aot \
 --require-entry 0x10410
ASCENSION_PRIVATE_AOT_C=/private/aot/ascension_private_aot.c \
 bash tools/build_ios_probe_ipa.sh
```
A compilação exige o runtime/RSX já preparados pelos scripts da
pipeline. O usuário trabalha apenas no iPhone: será necessário
provisionar um **executor privado macOS** que processe o ELF e gere
uma IPA distribuída por canal privado, nunca pelo Actions público.

## Limites e próximo gate obrigatório
Este commit **não gera AOT real do Ascension** no GitHub público, pois
a cópia privada GOWA.ELF não está presente no ambiente de build,
e o módulo histórico M2.3 não está arquivado no repositório.
O lifter M2 continua parcial, sem provar semântica integral,
memória, FP/VMX, threads ou SPU. Os testes sintéticos provam
somente o caminho AOT genérico.

Próximo marco: usar cópia privada NPUA80918 para produzir, validar
diferencialmente e assinar um primeiro módulo AOT real com entry
0x10410, chamando outras funções AOT ou HLE, sem falso sucesso,
com provas de estado PPU no dispositivo. Seguir ampliando cobertura
CFG e SPU/RSX, não o contador de passos do interpretador.
