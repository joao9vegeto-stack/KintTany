# AscensionRecomp M3.1 — Verified import manifest -> strict guest NID bindings

M3.1 introduces a generic converter `tools/build_import_binder.py`:
- Reads PS3Recomp `ppu_loader.py` imports JSON [library,nid,stub].
- Validates 32-bit, nonzero, instruction-aligned stub/NID, rejects collisions,
  caps entry count at bridge capacity and sorts bindings deterministically.
- Emits C registration through `ar_bind_import`, checking every return value.
- No fake CELL_OK: missing HLE still reports NID and halts.
- Preserves full `ppu_context` ABI when tested on pinned upstream header.

A C test links dynamically generated synthetic imports with synthetic PPC
code; all GitHub CI inputs are game-free and synthetic.

The user's **private** GOWA.ELF imports JSON has **350** unique guest stubs
and 350 unique firmware NIDs across 25 libraries. Local conversion succeeds
without duplicate addresses or malformed values. The generated title-specific
C and title metadata are kept private, not uploaded or committed.

**Caveat:** this is registration infrastructure, not implementation of
missing PS3 APIs or a claim of gameplay. The earlier 220/350 HLE count only
covered the general lib-source registry; other upstream context handlers
can exist and need separate functional validation.

Next: automatically bind known context-aware runtime handlers, validate
TLS/init and LWMutex ABI, expand private startup traces beyond 0x531CAC
while keeping every unsupported branch/syscall explicit.
