# M5.4.1 — root cause of physical iPhone -424

On 2026-10-15 the user provided screenshots from build 0.5.5 (M5.4).
Both LINEAR and SWIZZLED: `FALHA -424 · fase 2`; RSX/Metal/depth
`2/2/0`; pixels match the palette rotated by +1 of the SECOND draw,
rather than staying on the FIRST draw's colors. M5.3 multipass
2/2 and surface view 1, 0 upload, M5.2 dynamic 3/3 and cache
replacement 2, M5.1 guest draw 1/1 and M5.0 shader compilation all
passed. No rendering regression in the earlier pipelines.

Concrete source bug:
`m51_guest_textured_quad_palette_ex()` configures
NV4097_SET_DEPTH_TEST_ENABLE=1 with Z24S8, LESS and writes enabled;
AFTER the clear and immediately before vertex/index commands, a
legacy M5.1 unconditional NV4097_SET_DEPTH_TEST_ENABLE=0 canceled it.
The NVIDIA/RSX register dispatcher stores the most recent value,
so GPU pipeline depth_test=0 and depth-write=0, and all three quads
would draw over each other. The native Metal diagnostic counter
correctly reported zero depth draws.

Fix (only one state line): conditionalize that late depth-disable on
`!depth_mode`. M5.1-M5.3 (depth_mode=0) retain original GPU behavior;
M5.4 (depth_mode 1 on first pass, 2 on later passes) preserves LESS+
depth writes. M5.4.1 source-order regression test explicitly catches
a future unconditional depth disable after enabling.

**Requires device test:** M5.4 button twice, LINEAR and SWIZZLED.
PASS only if 3/3/3 actual Metal/RSX/depth draws and 4 correct
GPU pixels at ALL three phases. Then test M5.3 and M5.2 again for
non-regression. CI only proves builds/tests, not physical depth
occlusion. No commercial game data and no measured title FPS yet.
