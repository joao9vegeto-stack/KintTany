# M5.2 — Guest shader texture animation/cache coherency proof

M5.1.3 passed on the user's iPhone, including both linear and swizzled
guest RSX FP TEX0 textured draws (1 guest and 1 Metal encoded per draw,
2 VP instructions, 16 FP bytes). Previous M4.10 texture cache,
geometry, regular texture and M5.0 compilation diagnostics also passed.

M5.2 preserves the same proven actual NV4097 VP/FP indexed draw and adds
THREE complete GPU frames with one reused 8x8 guest memory texture address.
At each frame the guest's A8R8G8B8 bytes are rotated (palette offset 0,1,2),
while RSX registers remain identical. The engine's existing content-hash
cache mechanism must detect mutation and replace its Metal texture.
The test asserts EXACT position and color of four GPU render target pixels
in each frame (not merely a set of four colors), one guest shader draw and
one encoded Metal draw each frame, and >=2 successful texture cache
replacements/ uploads. These counters are from the actual RSX cache overlay.

**On iPhone:** press "M5.2 · TEXTURA dinâmica RSX" twice, recording
LINEAR and SWIZZLED. The result must show both OK, DRAW RSX/Metal 3/3
and >=2 replacements. Then test M5.1 and M4.10 for regressions.

ONLY the physical iPhone can establish actual Metal pixel correctness.
