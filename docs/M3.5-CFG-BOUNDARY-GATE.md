# M3.5 — Strict bounded PPU control-flow graph before lifting

Generic `tools/ppu_cfg_slicer.py` traverses every statically reachable
PowerPC64 instruction within a user-supplied function interval (<=512
words). Follows direct conditional/unconditional branches and the
fallthrough after linked calls, recognizes conditional and unconditional
bclr/bcctr, and refuses tail jumps outside supplied bounds, implicit
fallthrough off the end, and no observed return.

This prevents a previous concrete failure class: interpreting the FIRST
BLR as an unconditional end when earlier branches can jump past it.

Verified on 7 synthetic CFG cases. In a PRIVATE image check of the user's
authorized game executable, the interval 0x525C00..0x525DAC had 107
reachable PowerPC words, five linked calls, and one guest return.
This real routine previously failed conservative first-BLR truncation;
after full-bound lift and explicit registration the boot test reached
unresolved 0x52A78C and then, after translating that bounded routine,
0x52E3F4. No GOWA ELF, RAP or game-derived code is in CI or the repo.

Scope limitation: CFG reachability validates intervals, not ISA semantic
equivalence, memory safety, SPU/RSX services, full boot or gameplay. The
runtime still lacks native iOS app packaging and measured game FPS.
