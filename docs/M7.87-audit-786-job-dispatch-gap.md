# M7.87: M7.86 evidence and the missing native SPU job path

## M7.86 device capture

The `Log786.txt` capture runs for 1:36. It proves that the M7.85 lookup
blocker changed: all 18 WWS policy-module fingerprints resolve, and the SPURS
workers admit policy runs. The launcher stayed responsive on the report page.
Guest file reads reached 11,538,566 bytes, while guest RSX draws and presented
flips stayed at zero.

The large SPURS number is **WWS policy-module admissions**, not completed game
jobs. In the runtime, that counter increments when the scheduler claims a
worker slot; it is independent from a title job being found, lifted, run, or
completed. The M7.86 report did not collect those separate stages, so its
3,847,725 count cannot be used as proof that game rendering work ran.

`0x003C4FA4` remains the historical backedge marker in `func_003C4F98`; it is
not the current instruction address. The latest AOT entry in this capture is
`0x00669A14`, called from `0x004D653C`. The recent HLE ring identifies that
entry as `sys_lwcond_wait` (NID `0x2A6D9D51`). This is an import entry and caller
evidence, not an instruction-level sample. The report itself correctly says
the live PPC instruction PC is not measured.

## Structural gap against the PC port

The iOS build registers four embedded SPU images and the 12 KiB WWS policy
module. It does not build or register Ascension's game job modules or its
position-independent SPU fragments. The PC port's `relift.sh` has separate
`jobmods` and `fragments` stages in addition to `spu`; those stages produce
native lifted entries used by its job dispatch path. The iOS build currently
only compiles `runtime/m772-npua-spu/wws_pm_npua/spu_recomp.c` and
`spu_workloads.c` for the title's SPU registry.

This mismatch is consistent with the M7.86 screen: SPURS is active and the
game reads its data files, but no guest draw or flip appears. The log cannot
prove whether a job was ever requested, because it did not count job calls or
misses and the phone's exact NPUA job bytes were not present in the build
workspace. The next native lift needs those exact bytes; using the European
PC port's fingerprints blindly would risk binding a different regional image.

## M7.87 change

- Report SPURS policy admissions separately from actual title job calls.
- Count job-chain module lookup hits, misses, active runs, and runner returns, with the last
  binary fingerprint, size, and guest effective address.
- On a lookup miss, save one exact binary per fingerprint beneath the app's
  `Documents/AscensionSPU-…` directory. The new report action shares those
  binaries from the iOS Files sandbox.
- Keep the PPC instruction PC and rendered-frame claims fail-closed: only an
  actual guest draw and presented flip prove rendering.

The expected next artifact is the phone's captured SPU binary set. Those files
can be fed into PS3Recomp's native job-module lifter, registered in the iOS
build, and compared with the PC port's lift. M7.87 does not claim a first
frame; a subsequent device run must show job completions and then guest draws
and flips before that claim is warranted.
