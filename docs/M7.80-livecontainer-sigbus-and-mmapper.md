# M7.80 LiveContainer SIGBUS and mmapper integration

## Device evidence from `7.79.zip`

`IMG_5048_compressed.MOV` shows the selected `NPUA80918` installation and
`GOWA.ELF` accepted by the launcher. After starting Ascension, LiveContainer
returns to the Home Screen. The accompanying report records an
`EXC_BAD_ACCESS` / `SIGBUS` (`KERN_PROTECTION_FAILURE`) at `0x3645c0573` in the
AscensionRecompProbe image. The containing VM region is `VM_ALLOCATE` with
current protection `---` and maximum `rwx`: a thread in the compiled app read
a page that the process had reserved but could not read. The report does not
include the guest window base or a live runtime report, so it cannot establish
the exact guest EA or claim that VFS, HLE, or RSX initialization completed.

## Fixes

- Reserve exactly the exposed 3.5-GiB guest range (`0xE0000000`) as ordinary
  read/write memory. Remove the `PROT_NONE` reservation followed by selected
  Mach `vm_protect` / `mprotect` transitions. Both Mach VM and `mmap` still use
  kernel demand-zero backing; the change does not eagerly clear or physically
  allocate 3.5 GiB. The bridge's checked accessors continue to enforce the
  guest upper bound.
- Fix the next integration blocker found in the same path audit: mmapper
  reserves guest EAs from `0x20000000` through `0xB0000000`, all inside the
  production guest window. The old external-map helper rejected every such
  mapping because it overlapped the VM. Mmapper map now copies its allocated
  backing into the guest window, so both checked reads and PS3Recomp's direct
  `vm_base + EA` accesses see it; unmap copies guest writes back for remapping.
- Update the launcher VM description to show the actual 3.5-GiB read/write
  guest range. The next IPA is version 7.80.0.

The M7.80 CI regression also touches `0x045C0573`, the fault's offset from the
start of the displayed VM region. The IPS omits the guest-window base, so this
is a relevant in-range probe rather than a claimed guest EA. It also checks the
RSX and stack ranges, and exercises a production-sized guest VM through
mmapper reserve, map, guest write, unmap, remap, readback, and free. A CI pass
can establish those source/runtime checks and IPA build integrity; only a new
LiveContainer device run can confirm that this SIGBUS is gone or show how far
the game proceeds afterward.
