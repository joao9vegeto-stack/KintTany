# AscensionRecomp M5.5 — actual NV40 stencil-tested GPU draws

On 2026-10-15 the physical iPhone screenshots of **M5.4.3**
(0.5.6, build 56) proved both LINEAR/SWIZZLED:
`M5.4 PROFUNDIDADE RSX: OK`, 3/3/3 guest/Metal/depth draws,
far geometry occluded, nearer geometry visible, correct four GPU
pixels. M5.3 2/2 GPU multipass + native view=1 and upload=0,
M5.2 3/3 GPU dynamic TEX0 + cache replacements=2 also passed.
The -424 Z24S8 bug was genuinely resolved without regression.

M5.5 adds **actual RSX stencil** operations on guest NV40
TEX0 shader geometry:
- Pass 1: clear colour and stencil(0) in existing Z24S8 target,
  set stencil ALWAYS, ref=1, ZPASS REPLACE; write palette 0 and
  stencil 1, read back four GPU pixels.
- Pass 2: stencil EQUAL ref=2, no clears, ZPASS KEEP, palette+1
  is required to be FULLY REJECTED: palette0 remains across target.
- Pass 3: stencil EQUAL ref=1, no clears, KEEP, palette+2 is
  required to PASS: GPU readback must equal palette+2.

All passes must execute the actual decoded guest VP/FP TEX0 and
indexed geometry, with 3 guest draws, 3 Metal encoded draws, 3
stencil-enabled Metal pipeline/attachment counts, and 4 ordered
GPU pixel comparisons on EACH pass. A simulated host stencil, shader
replacement, or automatic success is prohibited.

Stencil probe uses depth_mode values 3,4,5, sharing proven Z24S8
configuration but disabling depth test/writes. M5.4 uses 1,2;
M5.1-M5.3 use 0. Existing paths and on-screen buttons remain.
No commercial game files anywhere in repository/Actions.

CI validates build, hook symbol, regression checks, SHA and archive
integrity; only user's iPhone proves actual GPU stencil. Tap the
new M5.5 button twice (LINEAR and SWIZZLED) and retest M5.4/M5.3.
This is still a SYNTHETIC renderer proof, not Ascension gameplay.
Next M5.6: MRT or per-pixel stencil write mask, then native title
bootstrap only when privately supplied ELF/PRX/assets are available.
