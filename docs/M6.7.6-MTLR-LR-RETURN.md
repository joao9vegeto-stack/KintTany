# AscensionRecomp M6.7.6 — restore LR and validate blr, not a fake jump

NPUA80918 real private device report M6.7.5:
- sys_initialize_tls NID 0x744680A2 returned correctly with real PT_TLS
  address 0x00839B28, filesz 12, memsz 384, main thread id 1;
  r13=0x0E007000 and guest resumed at PC 0x00669C34.
- At guest PC 0x00669C34, ld r0,0x20(r1) reads saved 0x0001058C.
- At 0x00669C38, 0x7C0803A6 is **mtlr r0** (PowerPC SPR 8),
  but M6.7.5 only supported mtspr to CTR (SPR 9), so it stopped
  at step 41 with code -1006. This is *not* an HLE failure.

M6.7.6 implements exact decoded SPR 8 mtlr on the opt-in TLS-aware
PPU48 engine; it stores all 64 guest LR bits and reports the
producer PC/LR value. CTR and LR remain independent, and all
unsupported special registers, mtspr Rc variants still fail closed.

Also implements exact unconditional blr (0x4E800020) in that
same bounded engine. Guest LR target is masked to a 4-byte
boundary and verified against ELF executable PT_LOAD file-backed
memory; missing, >32-bit and non-executable destinations return
-1022. CR-dependent bclr forms are not implemented and return
-1024, not guessed. No guest address becomes a native host pointer.
Earlier ABI wrappers continue to reject mtlr, preserving historical
M6.6/M6.7 tests, while the active M6.7.6 path supports it.

The test is built only from generated synthetic ELF data. After
real NID TLS HLE it uses guest PPC instructions to restore LR via
lwz from guest data, execute mtlr, then blr to valid guest code.
It also tests invalid return PC, unsupported conditional bclr
and illegal Rc mtlr. Existing CPU4/8/16/24/32/40/48 and M4/M5
RSX Metal fixtures remain unchanged.

already validated private NPUA80918 GOWA.ELF. Copy the report.
Expected minimum evidence: TLS still initialized=1, mtlr recorded
at PC=0x669C38 with LR=0x1058C, and blr will either reach
further executable code or reject an invalid target explicitly.
No full native boot or gameplay is implied by PPU48 tests.
