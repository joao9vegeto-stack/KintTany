# M7.96 first-frame audit

## Evidence in `3-796-2.txt`

- The guest entry remains active; 6,087,507 AOT function calls and 1,875,758 LV2 syscalls were recorded over 71 seconds. The report's “last PC” (`0x0066640C`) is the most recent function entry, not the current instruction address.
- `0x003C4FA4` is explicitly the sampled/back-edge marker for `func_003C4F98`; it is not a live PC.
- The most recent syscall context is number 141, LR `0x00419B10`, with `r3=30`. In the pinned runtime, 141 dispatches to `sys_timer_usleep`; the corresponding lifted function `func_00419AC8` polls a guest state and calls `usleep(30)` at `0x00419D54` before returning to `0x00419D1C`. This is a guest wait loop, but the report lacks the memory values needed to decide which producer it awaits.
- The report has 108,881 WWS PM admissions, but zero job-chain calls/returns, zero guest flips, and zero draws. These counters prove neither completed game jobs nor RSX presentation.
- The RSX host counters stop at 19 VBlanks and 65 FIFO drains. The report does not capture the FIFO `get`, `put`, current word/method, or lock owner, so it cannot identify the exact command where the worker stopped.

## PC and iOS behavior compared

The GoW Ascension PC runner exports `GCM_PARK_RESYNC_MS=2000000000`. Its FIFO walker only resynchronizes a standing `JUMP` park after that interval. The iOS patch used the same recovery point but set its equivalent `GCM_PARK_WAIT_MS` to 2000 ms. Resynchronizing can skip commands between `get` and `put`, including fences that guest code waits on. M7.97 changes the iOS park grace to the PC runner's 2,000,000,000 ms value.

The launcher also hid the real Metal layer when starting a guest and only revealed it after the first guest flip, creating a visibility cycle. The app now reveals the actual Metal layer before guest startup and prevents launcher-tab changes from hiding it during a live run. This fixes display visibility; it does not create a guest draw or flip.

## Address mapping limit

The AOT tree contains 29,849 lifted function entries, so static function-boundary lookup is possible. M7.96 did not record the live PPU CIA or a trace of every instruction; its sampled function entries and loop marker cannot support a truthful “all current PCs” map. The current artifacts also do not show the state read in `func_00419AC8` or the RSX FIFO command that stopped the worker. No safe patch to force the guest wait to return can be inferred from those missing values.
