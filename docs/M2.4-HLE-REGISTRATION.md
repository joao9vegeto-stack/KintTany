# AscensionRecomp M2.4 — Firmware import registration gap gate

This stage audits **registration availability**, not handler correctness.

Ascension's private ELF has 350 distinct imported firmware NIDs across 25
libraries. Highest counts: sceNp=49, cellSpurs=45, sysPrxForUser=30,
cellGcmSys=29, sys_fs=26, sys_net=23. These are metadata counts only,
without ELF code or license in the repository.

Pinned PS3Recomp upstream `gen_hle_nids.py --all` is run in Actions to inventory
the registered HLE NID set from every supported library. The generator's
--all switch avoids silently dropping entire libraries by typing a short list.

Use `python3 tools/hle_coverage.py --registry-source <generated.cpp> --imports <PRIVATE-GOWA.imports.json> --out <PRIVATE-report.json>`
to compare your local, private import manifest without exposing game data.

Results have three distinct meanings:
- A handler REGISTERED is only a mapping of NID to a callable pointer.
- A handler IMPLEMENTED must pass ABI/guest memory/return-value tests.
- A handler GAME-COMPATIBLE must pass against actual Ascension behavior.

Upstream unresolved-NID default may still fake success; our audit records
gaps explicitly but DOES NOT yet patch the full upstream runtime or implement
missing handlers. No native gameplay, SPU/RSX backend, FPS, or IPA claimed.

All branch isolation, one-commit/one-workflow and no public game bytes remain.
