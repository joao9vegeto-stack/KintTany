## Exact native ARM64 failure
```asm
main+0x227bd48 ldr x14, [x20, #0x38]         ; free-list bin table
main+0x227bd6c ldr x22, [x14, x11, lsl #3]  ; bin head
main+0x227bd70 cbz x22, ...
main+0x227bd74 ldr x15, [x22, #8]            ; current SIGSEGV
main+0x227bd80 ldr x22, [x22, #0x18]         ; list traversal
main+0x227bd9c str x22, [x1]                 ; previous distinct crash
```
At crash, `x14=0x3bd800000`, `x11=0x2f` (47), so the table entry at
`0x3bd800178` held `x22=0x5f6ad594929b1ff2`, an invalid pointer.
The failing access was to `0x5f6ad594929b1ffa`. The writer that corrupted
this table entry has **not yet been identified**. Do not NOP the dereference
or claim another larger root is a fix.

That table address lies inside an NVN device-shared memory pool
`0x3816ac000..0x3d20ac000`. Address overlap alone is **not proof** of
a GPU overwrite. Two `UnmapPhysicalMemory` requests within the active NVN
pool were refused with `ResultInvalidCurrentMemory`. Per [upstream memory
semantics](https://github.com/seedds/nxnative/blob/main/docs/reference/memory.md),
the protection is correct on Horizon; changing it blindly risks stale CPU/GPU
backing and more corruption. If the host's pool lifetime or registration is
incorrect, repair *that* rather than globally ignoring busy memory.

The 4GiB guest-root change is a possible overflow boundary for 32-bit
metadata but no such overflow has been demonstrated; keep it as a hypothesis.

## Required single global remedy
Audit and reproduce **the first write that corrupts the bin**, including
allocator insert/remove and region lifespan, physical map and unmap,
NVN pool-share registration and GPU writes, and 32-bit overflow risks.
Compare against the pinned NXNative `b526a50b85e4` and relevant upstream
changes before changing guest bytes or the host. Preserve Colab-built input,
external RomFS/AOC, existing shaders and unchanged Shell. Validate with
runtime memory invariants and then on real iPhone.

The 30/60 selector is packaged, but runtime stated `DM_FPS_TARGET` was
**not applied** because the main has no host-controlled frame step or
engine limit. A/B swap is packaged, but gameplay interaction is unverified.
