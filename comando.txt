### 1. Decodificação de endian em TODOS os endereços de memória do CP (correção principal)
Em `Runtime/XOWUEEngine.cpp`, crie e use em todo o processamento PM4:

```cpp
static inline uint32_t xenosGpuSwap32(uint32_t v, uint32_t endian) {
    switch (endian & 3u) {
        case 1u: return ((v & 0x00FF00FFu) << 8) | ((v & 0xFF00FF00u) >> 8); // k8in16
        case 2u: return __builtin_bswap32(v);                                 // k8in32
        case 3u: return (v << 16) | (v >> 16);                                // k16in32
        default: return v;                                                    // kNone
    }
}

// Igual ao xe::store do Xenia: aplica o swap e grava em ordem de bytes do host (LE).
// Para endian=2, o resultado em memória fica big-endian e o `lwz` do guest lê `value` exato.
static void xenosCpWriteback32(uint8_t* base, uint32_t rawAddress, uint32_t value) {
    const uint32_t endian = rawAddress & 3u;
    const uint32_t phys   = rawAddress & ~3u;
    const uint32_t stored = xenosGpuSwap32(value, endian);
    uint8_t* p = /* MESMA tradução física->host já usada no resolve/vertex fetch */;
    std::memcpy(p, &stored, 4);
}

static uint32_t xenosCpRead32(uint8_t* base, uint32_t rawAddress) {
    uint32_t raw; std::memcpy(&raw, /* tradução de (rawAddress & ~3u) */, 4);
    return xenosGpuSwap32(raw, rawAddress & 3u);
}
```

Aplique em TODOS os opcodes Type-3 que carregam endereço de memória:
- `EVENT_WRITE_SHD` (0x58): [initiator, address, value]. Se `initiator & 0x80000000`, o dado é o
  contador de swap/vblank do CP (como o `counter_` do Xenia), NÃO 0xDEADBEEF; senão, é `value`.
  Grave via `xenosCpWriteback32(address, data)`.
- `EVENT_WRITE_EXT` / `EVENT_WRITE_ZPD` / `EVENT_WRITE` com endereço.
- `MEM_WRITE` (0x3D): address = word0 (com endian), seguido de N dwords, cada um via writeback.
- `REG_TO_MEM` (0x3E): word1 = endereço com endian.
- `COND_WRITE` (0x45) e `WAIT_REG_MEM` (0x3C): quando o poll é em MEMÓRIA, leia com `xenosCpRead32`
  (máscara + swap). Quando o write é em memória, use `xenosCpWriteback32`.
- Writeback de `CP_RB_RPTR_ADDR` e `SCRATCH_ADDR`/`SCRATCH_UMSK`: mesma regra de máscara e endian.
Procure no arquivo QUALQUER `storeGuestBe32(`/`memcpy` que use endereço vindo de pacote PM4 sem
`& ~3u` e corrija.

Log (canal dos milestones, limite de 64 linhas):
`XENOS_CP_WRITEBACK op=0x%02X raw=0x%08X addr=0x%08X endian=%u value=0x%08X readback_be=0x%08X`
O `readback_be` deve ser `loadGuestBe32(addr)` logo após a escrita. Para endian=2 ele TEM que ser
igual a `value`.

### 2. Relógio do guest coerente (revertendo o "+831 por pump")
- Se existir `g_lastEmulatedTimebase` ou qualquer timebase que avance por pump, REMOVA.
- `mftb` (no patch do XenonRecomp) deve retornar o tempo monotônico real do host em ticks de 50 MHz:
  `ticks = clock_gettime_nsec_np(CLOCK_UPTIME_RAW) * 50 / 1000` (subtraindo o instante do boot).
  Use `__int128` ou divida antes para não estourar.
- `KeQueryPerformanceFrequency` deve retornar exatamente `50000000`, coerente com o `mftb`.
- `KeTimeStampBundle` (export de dados do xboxkrnl): se importado, atualize a cada 1 ms numa thread
  do host (InterruptTime e SystemTime em unidades de 100 ns, TickCount em ms), como no Xenia.
  Grave em big-endian. Sem isso, `GetTickCount` fica parado e loops com timeout nunca terminam.
- Log único na inicialização e no platô:
  `XOWUE_TIMEBASE mftb_delta_1s=%llu qpf=%u tickcount=%u bundle_import=%d`
  (o `mftb_delta_1s` precisa dar cerca de 50.000.000).
